## 1. 交付范围

- 仅 chat/completions：可信 `[DONE]` + `stop` / `length`，非空白思考、无正文、无任何工具片段，才进入有限续接。损坏帧、EOF、未知结束、过滤、错误和取消不触发；保留 DSML 既有纠偏，不把 DSML 剥空误认成纯思考。
- 一个 `RunAgent` 生命周期最多自动续接 2 次，占用正常 MaxSteps；工具成功、DSML 或计划 step 重置不刷新额度。额度不落库，不跨重启自动恢复。
- 每次真实思考先落库，usage 走既有记账；上限报错带结束原因、已知纯思考输出 tokens 和用量缺失标记。`length` 只描述供应商终止原因，不认定预算根因。
- 上下文引擎按本轮落库 seq 选择性补回 assistant `reasoning_content`，原文完整、顺序不变、每条一次，当前候选形状为 `content:""`；不伪造用户“继续”或 assistant 正文，不重放旧工具调用，普通历史过滤保持不变。
- 一次性说明只加到续接请求的 system；后续普通工具轮撤下说明，但保留本轮思考 overlay。估算、消息数、system 指纹与请求留痕纳入 overlay。
- overlay 存在时不自动压缩/改写历史；已被覆盖的材料不能完整回传则直接停止。普通下一执行轮仍沿用原压缩策略。
- 续接新增请求失败直接收口，不进入整步重发、公司/专家 fallback、overflow 强制压缩重发或备用地址故障转移；保留未完整送达前的同地址安全拨号阶梯。固定使用上个可信响应的实际地址，防止其他会话更新全局主备偏好而改变目标。
- `thinking_continue` 独立易逝状态显示 `1/2`、`2/2`，不是网络 retry；接回 SSE 补发当前提示。正常输出/工具开始、停止/插话、错误/done 清理，不清其他等待条、不丢保存思考。
- messages/Responses 未新增自动续接、签名持久化或原生 item 改造；`llmproto.go` 未修改。无新依赖、配置开关、供应商白名单或数据库迁移。

### 真实失败也保留

补充工具顺序测试第一次失败：`overlay order: map[thought:4]`。原因是合成调用使用未知工具名，被既有上下文修复过滤，无法构成有效工具顺序证据；改用合法无副作用进度工具后，同一顺序/调用次数断言通过，未放宽断言。后续回归还输出既有测试清理阶段日志 `sql: database is closed`，对应测试均 PASS；未顺手修改邻近交付队列代码。

只读审查会话 `f39d57938c93a4f95a` 指出 `completeMaterials` 的文本计数会把非 overlay 历史误拦，且相同文本可能冒充目标材料。专项测试 `TestThinkingContinueUnrelatedHistoryDoesNotBlock` 取得真实修前红：`ordinary request blocked by non-overlay reasoning`，`FAIL jxassistant 0.021s`。修正为 Message 上不序列化、不落库的请求内 seq 身份标记，只校验本轮选中 seq 的原文和恰好一次，不放松材料完整性；新增同文不同 seq、非 overlay 冒充拒绝断言。另显式否决同时带 usage 的 error 帧，并补运行体登记下的真实 `beginModelStream → pushPending → kickModelStream` 流中插话测试及 413 overflow 不重发。修后整组绿 `7.549s`。

审查关于“编译后即开放但真实未验”的阻断由经理在 2026-11-17 16:45 转达中裁定边界一致：允许完整源码集成，但仅留未编译分支/patch，后续必须由用户明确授权受控真实验证；不以离线绿视为门槛通过。其余建议中的完整计划审批 UI/DOM 视觉验证仍未做，不无限扩大本轮审计。

## 3. 真实兼容门槛仍未通过

官方依据仅支持：带 tools 完整回传 assistant reasoning_content、system role 和 assistant nullable content；**不能证明末尾“空正文且无工具”的 assistant 能在普通非 Beta chat 端点继续生成**。目前实现候选为 `content:""`，不是已经实测过的形状。

- [DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode)：带 tools 回传所有思考；无 tools 时历史思考被忽略。因此实现还要求本请求确实带 tools，不为无工具请求承诺连续材料。
- [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion)：字段 schema 不等于整包可续证明。
- [Chat Prefix Completion](https://api-docs.deepseek.com/guides/chat_prefix_completion)：Beta prefix 是另一能力；本实现不加 prefix、不改 `/beta` 或 URL。

现有 `POST /api/llm/ask` 只有 system/user/session/purpose，不能发送所需 assistant 尾包、工具目录或返回完整终态；`/api/providers/test` 也不足以验证。当前没有可用的完整产品调用入口。本次没有读 Key、扩权 ask、自建临时 HTTP 调试接口或运行脚本绕过配置保护。

经理已明确允许功能分支 RunAgent 集成及本地假流验证，以便验证计数/停止/overlay；不加默认 false 隐藏开关、白名单，也不据此宣称线上可用。当前运行中的实例没有改变。**若用户编译此分支，源码中的接入即会生效；所以在真实门槛未定前不要把“源码已完成”当作可以直接试编的建议。**

### 试编前需经理/用户决定的最小选项（本轮不实施）

1. **用户明确授权的试验性分支编译**：先确认无任务在跑，由用户编译本分支。此方式能覆盖真实产品 RunAgent/SSE/当前渠道，但会在该构建中启用所有满足条件的带 tools chat 续接，不能视作已验收版本；使用无敏感专用短测试会话、保持当前目标/档位/预算、工具仅定义且不执行。一旦模型请求工具应立即停下，不能靠此构造业务副作用或强迫 36k 长思考；短题未产生纯思考则只是未覆盖，不能宣称兼容。
2. **单独受控验证构建**：另行授权在与日常实例隔离的构建/测试环境中，由产品正常保护通道使用用户指定目标；可验证候选完整报文和失败收口，不能自动证明日常实例 UI/实际长思考状态。隔离、账号配置来源、预算及可见控制须先由用户/经理确定；本轮不创建构建、不复制配置、不取 Key。
3. **已有合法完整报文入口**：若用户已有可提交 tools＋assistant reasoning＋空正文＋system 的受控客户端入口，可先验证当前渠道接受候选报文和终态；只能证明协议兼容，不覆盖本产品计数、SSE、停止链路。当前已核对的 ask/providers-test 不满足此能力，不能硬拿它们代替。
4. 无上述明确授权/入口时仅保留本功能分支提交/patch供审查，暂不编译、不合 dev、不部署；不实现隐藏开关、新 HTTP 调试接口、配置/取 Key 脚本，不启用 Beta prefix 或静默降级为丢思考重跑。

成功验证应记录实际协议/脱敏目标、原 tools、完整 reasoning、空/null 形状、max_tokens 是否省略、finish_reason/usage、有效正文或工具产出及不执行工具的证据；若被拒，应保持原错误收口，不重复 POST 或换渠道尝试。

## 4. 收尾与剩余风险

- 两次续接仍可能全部耗在思考；额外完整回传增加输入费用和上下文压力，次数上限不是整轮 token/费用/耗时硬预算。
- 不能从原会话约 32928 字或“36k”界面观察推出当次 max_tokens/finish_reason，更不能认定原问题根因已确诊。
- 程序不重放旧调用，不等于模型不会再次请求同一副作用工具；本功能未引入通用去重。
- 当前结论仅为源码接入 + 离线程序行为证据，等待经理独立审查及真实兼容门槛决策，尚无用户验收。
- 无稳定项目知识修订建议；未自行维护项目事件/知识正文。
