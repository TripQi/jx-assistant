# 仅思考响应自动续接：设计方案（仅 chat）

> 待经理审定，未实施。基线 `dev@5cc11a93`；分支 `feat/thinking-only-auto-continue`；遵循项目知识 v3。阿柒 2026-11-17 16:14 明确首期仅做 chat/completions，messages/Responses 行为不变。本轮只提交本文，不改产品代码、不编 exe、不重启、不排网络。

## 1. 目标与现场结论

在**同一执行轮**收到可信终止的纯思考响应时，保存思考与用量，最多自动发起 **2 次可见的新续接请求**，争取产出正文或有效工具调用。不是原样重试 POST，不声称恢复模型内部推理状态，也不保证新预算足够。

证据与未知：

- 原会话 `e7869c761ef88d41d4` seq 278 为约 32928 字的 assistant 思考记录，seq 279 记录“只返回了思考内容，没有给出正文”；seq 113 亦有同类中断。经理会话 `bcc5c6acb50e5399ee` seq 6446 是阿柒“36k、DS 预算耗尽”的观察，seq 6465 授权先方案后实施。**字符数、界面显示量与 token 用量不能互换，尚不能确诊耗尽预算。**
- 异常当次实际协议/渠道、请求输出上限、usage、finish_reason 未从此次历史接口消息中查到；未访问受保护 config.json/data 或运行实例。用户说 DS 基本走 chat 是首期范围依据，不替代当次协议证据。
- `agent.go:1446,1525,1743–1753` 已收集 `StreamCompletion`，但纯思考仍保存后直接报错；`context.go:221–231` **先过滤无正文无工具 assistant，再映射 Thinking → ReasoningContent**。所以落盘不等于下次回传；只改成 `continue` 会近似重跑原问题。
- `llm.go:78–95` / `agent.go:1426`：主循环不设 MaxTokens，chat 序列化省略该字段，实际默认由服务端决定；不能拿 messages 的 `defaultMaxOutput=32768` 推断 chat 上限。

## 2. 触发与状态

全部满足才自动续接：

1. 当前目标实际协议是 chat/completions，且其续接报文形状已有兼容依据；不按“DS”模型名猜协议。
2. `err == nil`，收到 `[DONE]`，finish_reason 为 `stop` 或 `length`。分别标记“仅返回思考”和“输出达到长度限制”；length 不等于证明思考独占预算。
3. 原响应思考非空白，正文无非空白内容，**任何工具调用或工具片段均未出现**。半截/无工具名片段也否决；DSML 清理后变空不算纯思考。
4. 执行体未取消、未被插话打断，无待优先处理的新插话；本轮续接已用次数 < 2，既有 MaxSteps 尚允许下一请求。

不触发：EOF/未知或缺失 finish_reason、content_filter、HTTP/IO 错误、取消、空输出、有正文或任何工具片段。messages/Responses **完全沿用现有行为**，不为此功能新增诊断、自动续接或原生载荷改造。

状态：`请求 → 保存思考/用量 → 停止与插话检查 → 终态分类 → 兼容门槛 → 额度/步数检查 → 提示 n/2 → 新包请求`。

- `continuationsUsed` 在 RunAgent 外层循环前初始化；工具成功、DSML 纠偏、计划获批 step reset **均不重置**。只在新执行轮初始化，不跨重启自动恢复。一次续接占正常模型步骤。
- 最多原响应 + 两次续接的三份思考；中间穿插正常工具步骤也不能刷新额度。第二次续接仍只有思考则停止、明确报错并保留手动继续。
- 停止优先：发包前再次查 ctx；插话先落地，清除过时的一次性续接说明，按新任务继续，已用额度不返还；沿用 beginModelStream/kickModelStream 处理流中竞态。

## 3. 连续材料与合法 chat 报文

### 已有官方依据与缺口

截至 2026-11-17 查阅：

- [DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode)：带 tools 时应完整回传所有 assistant reasoning_content，包括未调用工具的回合；不带 tools 时思考被忽略。支持“保留原 tools + 原样回传”，**不证明无正文无工具的末尾 assistant 能继续生成**。
- [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion)：支持 system role，assistant content 可为 null；未明确保证仅 reasoning_content 的空 assistant 尾包续接。该页末条 reasoning_content 的 Beta prefix 说明与工具回传指南不完全同口径，不能过度推断。
- [Chat Prefix Completion](https://api-docs.deepseek.com/guides/chat_prefix_completion)：末条 assistant 须 prefix=true，且走 `/beta`。**本功能不启用 Beta prefix，不改 URL/协议。**

因此 chat 是唯一实施目标，但“实际渠道接受尾部空 assistant + 思考”的兼容性仍待证实；官方 schema 允许某字段不等于整包可用。mock 只能验程序，不能证明供应商接受。

### 请求专用 overlay（不改旧历史）

不全局放开 context.go 的空 assistant 过滤。由上下文引擎提供仅本执行轮有效、按落库 seq 定位的续接材料：

1. 保留原任务、历史正文、已执行工具与真实结果，不复制/重放旧 ToolCalls。
2. 将本轮纯思考记录按原顺序恰好补回一次，以 assistant `reasoning_content` 原文承载，`content` 使用**已验证的空/null 形状**；不截断、不总结、不当用户正文、不伪造 assistant 正文。后续正常工具轮仍保留这些本轮材料，直到执行轮结束。
3. 一次性短提示追加到本请求现有 system 说明，下一正常工具轮移除；不新增 user/aiuser“继续”。system role 有官方依据，但整包的末条 assistant 合法性仍须验证。
4. 引擎统一计算包含 overlay 的 token 估算/消息数/系统指纹及请求留痕。不得实际发新包却记旧估算。若压缩使必要思考材料无法完整保留，停止续接，不静默丢材料后重跑，也不为续接强制改写历史。

建议系统说明：

> 上一响应仅返回思考，未产生正文或工具调用，该响应未执行工具。请基于原任务、已完成结果与可用思考材料，给出下一步有效工具调用或最终答复，避免重复推演。

“该响应未执行工具”不冒称整轮没执行。提示只说明事实与期望产出，不降低思考档位、不强制工具、不越过审批。不保证模型不会重新推演，但避免丢思考后原样重跑。

### POST 边界

`llm.go:496–533,828` 的 submittedRequestError 表示 POST 可能已处理但未收到响应，继续禁止原地址/备用地址/整步重发。该保护不变。

本功能只在上次响应已有可信结束且保存记账后，携带新增材料和说明发新请求；body 不同、可见提示、照常计费。不清旧用量，不切模型/渠道/备用地址/档位，不改输出上限。

新增续接请求若失败，首期建议直接按原错误收尾，不进入整步 POST 重放、自动 fallback 或 overflow 强制压缩重发；保留既有“尚未发送成功”的同地址安全拨号重试，但不转备用地址。仅约束新增路径，不改全局重试语义。

## 4. 最小改动与可见行为（实施阶段）

| 文件/域 | 职责 |
|---|---|
| `agent.go` + 小型续接 helper | 全轮计数、保存后分类、停止插话优先、请求失败收口；原工具执行段不变 |
| `llm.go` | 如现有回调不足，增加原始工具片段观察；不动预算、鉴权或传输重发保护 |
| `contextengine.go` + 请求专用 helper | seq 定位的本轮 overlay、一次性 system 说明、含材料的估算/留痕；普通 context.go 过滤不变 |
| 状态事件、必要的 `web/app-chat.js` 小改 | 独立 thinking_continue 提示/清理，不冒充网络 retry |
| 定向测试 | 触发矩阵、额度、连续请求、停止插话、用量/UI |

复用 message/thinking 落盘、meterUsage/RecordCall、runError 和停止机制。审计补 protocol、Ended/raw reason、对应 seq、续接次数/拒绝原因、usage 是否缺失即可；不另存敏感请求副本。无需新依赖、配置开关或数据库迁移。**不改 llmproto.go 的 messages/Responses 续接，不扩修签名、原生 item、MCP 等邻居。**

每次保存后 emit message，原思考折叠保留，不发“上一输出作废”的 retry。状态条显示“本轮仅返回思考，自动续接（1/2）”，预算原因另注；有效输出、停止、插话、错误、done 均清提示。超限报“本轮已自动续接 2 次，仍仅返回思考，已停止，可手动继续”，显示结束原因与可得用量，缺 usage 明确未知。手动继续是用户新动作，不后台自启。

## 5. 验证与开放门槛

先补 chat 兼容证据，再决定目标渠道是否启用；不做“默认所有兼容端点都接受”的猜测。

1. **真实渠道形状（尚未执行）**：经合法调用入口，以无敏感短题、仅定义且绝不执行的无副作用工具，验证“原工具目录 + 完整 reasoning_content + 空/null assistant 尾包 + system 说明”能接受并产生正文/工具。记录脱敏协议/目标标识、原包 max_tokens 是否省略、finish_reason/usage 和有效产出。保持原模型/档位/预算，不读 Key、不执行真实业务。无合法入口则交经理协调，不绕过配置保护。
2. **修前红/修后绿**：overlay/可回收本地流夹具证明旧实现报错、新实现按规则发送不同新包，不改生产树造红、不放宽断言。mock 证据只证明程序。
3. **触发表**：stop/length；EOF/缺终止/未知原因/过滤/错误/取消/空白/有正文/半截工具/DSML 残渣均不误触发。
4. **额度/步数**：三次纯思考只产生两次额外请求；工具成功和 plan step reset 不刷新额度；MaxSteps 提前收口；新执行轮才重置。
5. **请求/账目**：任务与已执行结果连续、思考原文各一次、无虚构用户/工具/正文、历史不变、目标/档位/预算不变；每次思考与 usage 分别保留，估算/请求日志一致。
6. **停止/插话/UI**：发包前取消不再 POST，流中可停，插话不沿用旧说明；回看/重连不重复或丢思考；提示及时清理；报错不伪造成对话正文。
7. **回归**：reasoning stub、completion reasons、已送达 POST 禁重放、停止插话；增加 messages/Responses 不进入新增续接路径断言，不修改其现有语义。

测试先协调窗口，前台串行无管道，命令 timeout ≤300 秒，只定向；不 go build、不编产品 exe、不重启、不全量、不扫描 `.jxai`，临时夹具放 `.jxai/tmp/`。

## 6. 风险与下一步

- 仍未核实原异常的协议/上限/结束原因，不能宣布已找到预算根因；实际 DS 中转渠道也不等于官方行为。
- 两次仍可能全部耗在思考或撞上下文窗口。次数上限只约束**新增续接**，不是整轮费用/token/耗时硬预算；已有工具循环仍受既有步数和停止机制控制。
- 程序不重放旧调用，但模型仍可能主动再请求同一工具；不加通用工具去重以免误伤合法重试，不承诺绝无重复副作用。
- 完整思考回传增加输入与缓存压力；不能裁剪材料或偷改档位/上限来提高成功率，不承诺节省 token。
- **当前交付是方案，不是兼容性验收或产品修复。** 审定后先补实际 chat 形状证据；通过才启用自动续接，失败则保留思考和明确错误、手动继续，向经理反馈实质新取舍。同方向无需再次让阿柒重复批准。
