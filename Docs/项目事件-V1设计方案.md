# 项目事件 V1 设计方案

- 初稿及本次修订日期：2026-11-15。
- 状态：产品口径已确认的实施基线，尚未实现；本轮只修订文档。
- 定位：默认内置、默认启用的独立“项目事件”组件，建议 ID 为 `project-events`，在设置页查看维护，数据进入现有 `jx.db`。
- 配套方案：[项目知识库 V1 设计方案](项目知识库-V1设计方案.md)。
- 两份 Docs 为唯一有效基线，取代旧记忆改造 v1.1 草稿的冲突条款；本文确认的行为及长度数值必须落实，能力名、表名、模块文件名属于实现建议。

## 1. 产品原则【已确认】

1. 以相对独立、可独立验收的目标作为一条事件，不按会话、派发或修复尝试次数建事件。
2. 按项目按需查询，默认按修改时间倒序返回十二条，支持时间范围、关键词、状态及分页。
3. 只保存当前概况、最近进展及关联会话，不复制原文、工具日志、代码和完整过程，不保存事件历史正文。
4. 保留摘要、最近进展和最近进展会话，先了解近况，再按需要追查来源，不默认遍历全部会话。
5. 标题最多 40、摘要最多 120、最近进展最多 100 个 Unicode 字符；描述各一句话，超限拒写并给修正指引，不截断。
6. 长期助理跨项目查写；五种工作模式查写自身项目；`aux` 只读自身项目，实际权限档仍须满足写入要求。
7. 两组件共用宿主项目登记和工作区绑定，但独立开关，事件不占知识正文预算、不自动全量注入。
8. 归档项目只读可查；永久删除项目或单条事件仅用户在设置页确认执行，不删除来源会话和工作区文件。

## 2. 事件身份与粒度

判断标准：这些工作是否围绕同一目标，能够由用户作出一次相对独立的验收？

| 场景 | 记录方式 |
|---|---|
| 同一个 Bug 多轮修复，用户尚不满意 | 同一事件持续更新 |
| 排查、实现、评审、验证分给多个会话 | 同一事件关联多个会话 |
| 同一功能前后端共同交付验收 | 同一事件 |
| 一个会话处理多个独立问题 | 多个事件关联同一会话 |
| 原目标之外增加独立需求 | 新建事件 |
| 已验收后出现新的独立复发 | 通常新建，可选关联旧事件 |
| 用户明确原问题没解决，继续返工 | 沿用原事件并修正状态 |

事件与 sessions 是多对多关系，`event_id` 稳定不变，不使用 `session_id` 代替身份，不凭相似标题强制合并。

纯闲聊、读记录或无独立跟进目标的临时询问不强制登记，每条消息、每次派发和每次工具调用均不自动生成新事件。

默认十二条不是去重依据；创建前还可按关键词或当前会话关联寻找已有目标，不能因旧事件排到列表后面就重复创建。

## 3. 当前概况与最新来源

| 字段 | 回答的问题 | 何时更新 |
|---|---|---|
| `summary` 事件摘要 | 这是什么事，整体到哪里？ | 整体结论、目标或主要阶段变化 |
| `latest_progress` 最近进展 | 最近一次有意义的推进是什么？ | 新事实覆盖旧进展，不追加日志 |
| `latest_session_id` 最近进展会话 | 优先去哪个会话核实最新情况？ | 随最近进展一起明确来源，不取最后活跃会话 |

示例均为虚构：

```text
标题：修复示例输入重复
状态：待验收
摘要：首轮修复未解决，后续已处理回调竞态并等待用户验收。
最近进展：第二轮针对性测试通过，尚待实际输入验证。
最近进展会话：session-example-b
关联会话：共 3 个
```

最近进展会话必须属于关联 sessions，可附 `latest_message_seq` 定位来源消息，但不强制填写；填了必须确认消息属于指定会话。用户设置页直接更新时允许无会话来源，明确展示“用户更新”，不创建假会话。

AI 更新进展应指定实际来源会话，不能保留上一轮错误指针；无需把长期助理转述所在会话自动当成执行来源。没有读取的原文不能声称已经核实。

会话被删除后保留事件概况、原关联 ID 和来源不可用状态，不删事件、不编造替代来源；后续不涉及来源的编辑不应因历史来源已缺失而全部被锁死。

## 4. 一句话及硬限【已确认】

| 字段 | 上限 | 格式 |
|---|---|---|
| `title` | 40 个 Unicode 字符 | 单行短语 |
| `summary` | 120 个 Unicode 字符 | 一句话，说明整体 |
| `latest_progress` | 100 个 Unicode 字符 | 一句话，说明最新事实、阻碍或待验证项 |

按 Unicode code point 计数，标点与内部空白计入，不按字节或 UTF-16 code unit 计数；三字段均非空，未实施时可写“方案已登记，尚未开始实施。”。

每条最多 260 个描述字符，十二条最多 3120 个描述字符，结构字段仍有额外开销；该估算不是 token 数，也不是知识库预算单元。

### 4.1 权威校验与错误指引

- 去除首尾空白后校验长度与非空；字段含换行、分段、列表格式时拒绝，不靠删换行把多段揉成一行。
- 描述各用一句话，允许逗号连接必要信息，不允许多句、分号串或变相流水账；标题只作短语，不塞过程。
- 字符数和单行是硬规则，后端只拒绝明确多句格式，不承诺理解自然语言语义，不开发复杂语法分析器。
- 识别明显句界时包含中文 `。！？`、英文 `! ?` 和句末英文点号；内部句界后仍有叙述则拒绝，分号 `；;` 及省略号不能作为拼接多条进展的绕过方式。
- 无句末标点或正常句末标点均可；小数、版本号、域名、文件名、路径和代码引用中的英文点号不当作句末标点，具体词法规则用测试锁定，不逐个点号机械分句。
- 模糊情况依赖生成和编辑约束，不引入额外模型润色，不因检测困难放开字符硬限；具体标点词法实现不得声称是完整语言解析。
- 任一字段超限或格式不符，整次保存拒绝，返回字段名、当前字符数、上限和“压缩成一句话/去掉换行后重试”的明确指引；原记录、版本、时间均不变，绝不静默截断。
- 界面显示字符计数；工具、设置页及未来导入入口共用后端规则，不增加长备注、评论或进展历史字段绕过限制。

### 4.2 校验样例（实施时转成测试）

| 输入（摘要或进展） | 预期 |
|---|---|
| `已完成修复，等待验收。` | 通过 |
| `已完成修复，等待验收` | 通过 |
| `已完成 v1.2.3 兼容修复，等待验收。` | 通过 |
| `已将阈值改为 3.14，等待验证。` | 通过 |
| `已定位 config.go:334 的问题，尚未修改。` | 通过 |
| `已核对 a.b/c 路径，等待验证。` | 通过 |
| `已核对 example.com，等待验证。` | 通过 |
| `Fixed the regression, awaiting verification.` | 通过 |
| `已完成修复。等待验收。` | 拒绝，合成一句 |
| `Fixed it. Awaiting verification.` | 拒绝，合成一句 |
| `已修复！还有一项待查。` | 拒绝，合成一句 |
| 含换行、列表、分号串或超长内容 | 拒绝并提示对应修正 |

上述规则约束事件字段，不限制设计文档本身的句数。

## 5. 状态与完成事实【已确认】

状态固定为：讨论中、处理中、待验收、已完成、暂停、取消。

新建未传状态默认“讨论中”，所有入口一致；确已开始处理时显式设为“处理中”。派发、登记不代表实际执行，空闲、停止或异常退出也不代表完成。

要求用户验收时，执行会话报告完成进入待验收，用户认可后才标已完成；无人工验收要求时完成约定验证即可完成，但不能伪称用户已验收。

用户反馈未解决时沿用原事件回到处理中，摘要与进展反映事实；尚未继续执行不写“正在修复”。已完成、暂停或取消都保留记录，不自动清理。

不引入审批流、工时、负责人体系、任务依赖图或完整工作流引擎。

## 6. 项目共享、生命周期与权限

### 6.1 共享项目服务

使用同一 `project_id`、绑定表和路径解析，职责见知识库方案 §2；建议宿主 `projects.go` 提供项目服务，`store_projects.go` 提供 Store 数据访问，事件组件不维护第二套登记。

项目新建、路径绑定、归档、恢复、永久删除与预算上限管理均仅用户在设置页执行；未登记时引导设置页，任务可继续但不错误入库。

项目身份和事件归属固定：重绑目录不迁移旧事件，普通会话按当前绑定取得访问资格；已有历史关联不因当前路径重绑自动失效或改归其他项目，新增关联仍须核验权限与归属。

### 6.2 状态与开关

- 使用中项目正常查写；已归档项目只读可查，停止知识自动注入，不停止运行任务，后续内容或关联写入拒绝并提示由用户恢复项目；用户仍可执行恢复或经确认的永久删除。
- 关闭知识库组件不影响事件，关闭事件组件不影响知识库，两者均不删除共享项目和数据。
- 永久删除项目仅设置页确认执行，删除绑定、知识、事件及事件关联行，不删 sessions、消息、代码或工作区文件。
- 单条事件删除同样仅设置页用户确认执行，删除事件及其关联行，不删除来源会话；AI 工具不提供删除能力，可暂停或取消事件。
- 重复事件由用户确认后整理，不在 V1 做自动合并引擎；不因归档或组件关闭自动清理事件。

### 6.3 角色映射与 AI 入口【已确认】

| 模式 | 事件查询 | 事件新建/更新 |
|---|---|---|
| `assistant` 长期助理 | 跨项目 | 使用中项目，跨项目维护 |
| `task / office / coding / beginner-coding / skill-create` | 自身绑定项目 | 自身绑定且使用中的项目 |
| `aux` 只读答疑 | 自身绑定项目 | 不允许 |
| 用户设置页 | 全部项目 | 使用中项目可编辑，归档项目只读；管理入口可恢复或确认删除 |

两个组件 AI 能力统一走 `component_call`，长期助理也如此，不另开 `call_api` 写通道；事件清单必须覆盖 `assistant` 与五个工作模式，查询还覆盖 `aux`，写入不能包含 `aux`。

权限是交集：角色、实际权限档、组件开关、项目状态及项目归属均需通过。依赖独立任务修复的公共 `Writes` 门，实施前确认已落地；read-only、计划模式和缺失合法会话上下文拒绝写，workspace-write/full 也不能跨越角色边界。

普通会话不能通过伪造 project_id、event_id 或关联会话 ID 访问其他项目；普通会话新增关联只能是当前可确认归属同项目的会话，已有历史关联缺失或路径重绑不改变旧事件所有权。

长期助理关联来源应有明确依据（同一目标、执行/评审链或用户明示），这是助理判断契约；服务端验证存在性、权限、可验证的归属和关联一致性，不假装有“业务相关性校验函数”。设置页复用业务服务，不作为 AI 绕过权限的通道。

## 7. 单库表结构与并发【已确认，名称为建议】

全部进入当前实例既有 `jx.db`，遵守分表不分库，不另建项目域数据库；项目登记属于实例域，不自动跨不同 dataDir 同步。

复用现有 Store 连接、事务及 `storeMigrations`，结构升级追加迁移并经 `schema_migration` 记账，不改历史迁移，不将项目数据迁移写进程序目录资源迁移账本。

| 表 | 主要字段 |
|---|---|
| `project_events` | id, project_id, title, summary, status, latest_progress, latest_session_id, latest_message_seq, created_at, updated_at, revision, related_event_id（可选） |
| `project_event_sessions` | event_id, session_id, linked_at，(event_id, session_id) 联合唯一 |

事件到项目使用外键，删除项目清理事件；关联行到事件使用删除级联，不得让事件或关联删除级联到 sessions。为保留已删除会话的来源 ID，不对 session_id 设删除即清理来源的级联关系，存在性在新关联入口核验。

可选关联旧事件 `related_event_id` 仅指同项目，旧事件删除时清空引用而非删除新事件。索引建议 `(project_id, updated_at, id)`，关联表对 session_id 建索引。

### 7.1 事务与时间

- 使用 PATCH 语义提交变化字段与 `expected_revision`，版本冲突拒绝，要求重读合并，不能强行覆盖。
- 文本、状态、来源与关联更新在同一事务完成；新增关联去重追加，不整体覆盖别的会话刚补的关系。
- 确有内容、状态或关联变化才增 revision、更新 updated_at；读取、打开设置页、重复关联或相同值保存均不刷新。
- 时间由宿主生成，存 UTC、展示带时区，不接受调用方伪造修改时间；updated_at 是记录修改时间，不一定是代码落盘时间。
- 更新进展时一并明确来源，摘要可独立更新；任一保存失败均保留完整旧记录、时间与版本。
- 不保存事件历史正文、每轮进展日志或自动摘要历史，revision 只用于并发控制；通用审计不等于提供历史时间查询。

版本校验只防并发覆盖，不能判断旧回报内容是否过时；助理必须核对新事实，晚到的旧回报不应覆盖更晚实际进展。

## 8. 查询与写能力

能力名为建议，走现有组件协议，不新增工具路由。

### 8.1 `project_events_query`

输入：project_id（普通会话可推导）、from、to、keyword、status、可选关联 session_id、limit、cursor。

- 默认十二条，单页最多四十条；非法或超限 limit 拒绝并指导改为 1—40 或翻页，不静默截断结果条数参数。
- 排序 `updated_at DESC, id DESC`，使用二者构成的游标翻页，时间相同时稳定排序；不承诺并发修改期间为冻结快照。
- 关键词按普通文本同时匹配标题、摘要、最近进展，任一命中即匹配；参数化查询，`%`、`_` 等不意外变成通配符，不引入向量或全文检索引擎。
- 时间范围按最后修改时间筛选，状态按指定状态筛选，关联会话过滤用于找本会话已参与的旧事件；组合条件使用交集。
- 返回 ID、标题、状态、摘要、最近进展、修改时间、最近来源会话与可选消息位置、关联数量、revision、项目归档状态及下一页信息。
- 不默认展开全部关联 ID，不读取会话正文；无项目、未绑定、无结果分别明确说明，不回退其他项目。

### 8.2 时间语义

`from <= updated_at < to`，缺省不限时间；界面日期按用户本地时区转换，跨时区工具参数需明确偏移或 UTC；非法范围拒绝并指导修正。

它回答“最新修改时间在此范围内的事件”，不是“此期间曾经发生过的全部推进”；昨天更新、今天又更新的事件按昨天筛选可能看不到，工具及设置页都要说明这一限制。

最近十二条仅为单页数量，不是保留条数或天数。若需要历史过程应选读关联会话，不为此增加进展流水。

### 8.3 `project_event_get`

按 event_id 返回概况，分页列关联 sessions，默认二十条、单页最多四十条，超限拒绝并指路分页；附必要会话标题和来源不可用状态，不自动全文读取或总结会话。

### 8.4 `project_event_create` / `project_event_update`

创建返回 event_id 和 revision；更新带 expected_revision、变化字段及去重追加的关联会话，需要移除关联时显式提交并确保最新来源一致。

创建前查当前会话关联、关键词或近期事件，同目标复用 ID；没有找到不等于不存在，不凭相似标题强制合并。来源与字段错误返回具体修正指引，禁止用截断内容凑保存成功。

V1 不暴露 AI 删除、项目结构管理或事件全文长描述能力。

## 9. 维护时机与读取顺序【已确认】

### 9.1 登记与更新

1. 长期助理安排或普通工作会话开始跟进独立目标时，先查询已有事件，新建或复用 ID。
2. 派发、返工、评审继续携带 project_id、event_id，新会话追加关联，不逐派发创建新事件。
3. 阶段变化、验证结果、阻碍或用户反馈才更新，最近进展覆盖旧值，整体结论未变无需重写摘要。
4. 回报到达后先读当前版本，核实是否为新事实，避免旧回报盖掉新状态；无变化不保存、不刷新排序。
5. 记录失败如实说明，不能声称已登记，也不能因此把已经完成的原任务说成执行失败。
6. 工作会话可直接维护事件，但知识正文仍只提建议；任务回执向长期助理提，直接会话向用户提。

V1 通过工具与简短维护指引由助理主动登记，不自动扫描旧历史回填、不额外后台调用模型生成摘要；不宣称系统保证每项工作必有记录，验收检查漏记情况。

### 9.2 按需深入

用户问近况 → 查事件 → 用摘要和最近进展回答 → 不足时先读最近进展会话的摘要或来源消息 → 追查历史再选读其他会话。

事件正文不默认注入所有会话，能力清单只短提示可查询；不把未读取原文说成已验证，不自动遍历全部 sessions，不因为模型上下文不足静默换模型或渠道。

## 10. 设置页与保留策略

设置页提供项目选择、时间范围、状态、关键词筛选，默认十二条并加载更多；展示摘要、进展、修改时间和来源入口，详情分页查看关联会话。

编辑区显示三字段字符计数及一句话要求，并发冲突保留用户草稿、提示重读合并；来源缺失明确显示，不为了保存硬塞来源。

归档项目标记只读并可查询，项目恢复由共享管理入口执行；永久删除项目或单条事件均需用户确认，说明仅清理索引不删除 sessions 和文件。

已完成、取消事件不自动清理，当前事件不保留历史正文；误建重复由用户确认后整理。组件关闭不丢数据，未登记引导设置，不做大型任务看板、评论流或长日志编辑器。

## 11. 实施边界与验收

本轮只修订文档，不修改功能、配置、实际数据，不编译重启；实施先协调写入窗口，从届时最新 `dev` 建功能分支。

复用知识库方案中的共享项目服务、单库迁移与公共写权限门，旧 v1.1 的逐派发日志由按目标事件取代，不并存另一套流水。

验收重点：

- 同 Bug 多轮派发仍为同事件，一会话可参与多事件，携带 ID 后正确续写，不凭相似标题自动合并。
- 多路径共享且跨项目隔离，重绑不搬历史，组件独立开关，项目登记属于实例域。
- 默认状态讨论中；已执行显式处理中，待验收与完成事实一致，无验收不伪称用户认可。
- 标题 40、摘要 120、进展 100 的边界及 Unicode 计数正确，覆盖 §4.2 样例，超限/换行拒写给修正指引，无截断。
- 默认十二条、单页四十上限、时间范围及本地时区、三字段关键词、关联会话过滤、稳定排序和分页正确。
- 来源必须属于关联，seq 匹配、用户无来源、来源后来删除、目录重绑的历史关系均正确处理。
- `assistant` 跨项目，五种工作模式仅本项目可写，`aux` 只读；read-only/计划模式/缺失合法会话上下文拒写，workspace-write/full 仍受归属及项目状态限制。
- 并发冲突不覆盖，晚到旧回报不能因修订号最新就冒充最新事实，无变化不刷新修改时间。
- 归档只读可查、恢复可写，单条事件及项目删除只由设置页确认，级联清理关联行不删 sessions、消息或文件。
- 查询不读会话正文、不自动展开全部关联 ID、不自动注入事件列表、不增加历史正文恢复或模型切换。
- 设置页和工具共用校验，用户草稿冲突不丢，原任务结果与事件登记失败分开说明。

本方案无待定的产品长度参数和角色权限口径，具体命名与模块拆分在实施时核对现有代码，不擅改以上确认边界。
