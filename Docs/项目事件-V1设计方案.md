# 项目事件 V1 设计方案

- 方案日期：2026-11-15。
- 状态：设计稿，尚未开发，本轮仅沉淀文档。
- 定位：独立、默认内置的“项目事件”组件，以 SQLite 保存项目近期事项的轻量索引，在设置页查看与维护。
- 配套方案：[项目知识库 V1 设计方案](项目知识库-V1设计方案.md)。
- 说明：已确认产品原则与建议实现分开标注，接口名、表名及具体长度数值为 V1 建议基线，实施时先核对既有机制。

## 1. 已确认的产品原则

1. 按项目查询最近发生了什么，默认按修改时间倒序返回十二个事件，支持时间范围查询。
2. 一件相对独立、可独立验收的目标是一条事件，不把会话、派发次数或修复尝试次数当作事件数。
3. 只保存事件概况与关联会话，不复制会话原文、工具日志、代码或完整处理过程。
4. 保留“事件摘要”“最近进展”“最近进展会话”，帮助助理优先定位最新情况。
5. 所有事件描述用一句话解决，必须有长度硬限制，不能演变为多段总结或流水账。
6. 长期助理和普通助理均有查询与修改事件的权利，设置页也可查看、编辑。
7. 使用 SQLite 存储并加入默认内置组件，不在本轮实现功能代码。

## 2. 事件身份与拆分边界

核心判断：这些工作是否围绕同一目标，能够由用户作出一次相对独立的验收？

| 场景 | 记录方式 |
|---|---|
| 同一个 Bug 多次修复，用户尚不满意 | 同一事件持续更新，关联新增会话 |
| 排查、实现、评审、验证分给多个会话 | 同一事件，关联多个会话 |
| 同一功能分前后端实现并共同验收 | 同一事件 |
| 一个会话处理多个独立问题 | 多个事件可以关联同一个会话 |
| 原目标之外增加可独立交付的新需求 | 新事件 |
| 已完成后出现新的独立复发 | 通常新建事件，可用可选 related_event_id 关联旧事件 |
| 用户明确说原问题没解决、继续返工 | 继续原事件并修正状态，不伪造一次新完成 |

事件与会话是多对多关系，event_id 稳定不变，不能使用 session_id 代替，也不能凭相似标题自动合并。

默认不因每条用户消息、每次派发、每个工具调用而新建事件；纯闲聊、查阅记录或无独立跟进目标的临时询问不强制登记。

## 3. 三个概况字段的职责

| 字段 | 回答的问题 | 更新方式 |
|---|---|---|
| 事件摘要 summary | 这是什么事，整体到哪里了？ | 整体结论、目标或主要阶段变化时更新 |
| 最近进展 latest_progress | 最近一次有意义的推进是什么？ | 新进展覆盖旧进展，不累计追加 |
| 最近进展会话 latest_session_id | 最新进展优先去哪里核实？ | 与最近进展配套更新，不自动取最后活跃会话 |

示例数据均为虚构，不指向实际会话：

```text
标题：修复输入内容重复出现
状态：待验收
摘要：首轮修复未解决，后续已处理回调竞态并等待用户验收。
最近进展：第二轮针对性测试通过，尚待实际输入验证。
最近进展会话：session-example-b
关联会话：共 3 个
```

最近进展会话必须属于关联 sessions，可附可选 latest_message_seq 直达来源消息，不能为“看起来最新”而选择不相关会话。

用户通过设置页录入进展且没有来源会话时允许为空，展示“用户更新”；不为此创建虚假会话。

## 4. 一句话与长度硬限制

### 4.1 V1 建议数值

| 文本字段 | 硬上限 | 格式 |
|---|---|---|
| 标题 title | 40 个 Unicode 字符 | 单行短语，不放过程描述 |
| 事件摘要 summary | 120 个 Unicode 字符 | 一句话，不重复堆放历史 |
| 最近进展 latest_progress | 100 个 Unicode 字符 | 一句话，只描述最新事实、阻碍或待办 |

数值是建议实施基线，默认不向模型提供无限扩容选项；规则适用于所有语言，按 Unicode code point 计数，不按字节或 UTF-16 code unit 计数，空白和标点同样计入。

每条事件最多 260 个描述字符，默认十二条最多 3120 个描述字符，结构字段仍有额外开销，此估算不是实际 token 数或知识库预算单元。

### 4.2 写入校验

- 新建事件要求三个文本字段均非空，尚无实施进展可写“方案已登记，尚未开始实施。”。
- 先去除首尾空白，再校验长度、非空及单行要求，拒绝换行、分段、列表和额外备注字段。
- “一句话”是生成与编辑契约，服务端拒绝明显多句描述，不引入模型调用来润色或判断。
- 建议允许无句末标点或一个句末标点，识别明显多句时区分小数、版本号及合法标识符中的点号，不能简单按每个英文句点分句。
- 一句话仍超长时拒绝保存，返回出错字段、当前长度和上限，要求调用方压缩，不静默截断或拼接。
- 界面显示字符计数和格式提示，工具、界面和任何导入入口共用后端校验，不能只限制输入框。
- 不增设长描述、评论区或进展历史文本来绕过限制，细节留在来源会话中。

文档本身不受上述一句话规则约束，该规则约束的是存储和返回的事件描述字段。

## 5. 状态与事实口径

建议最小状态集：讨论中、处理中、待验收、已完成、暂停、取消。

- 会话报告修好了通常进入待验收，不自动等于用户满意。
- 有明确用户验收要求时，需用户确认才能标已完成；无人工验收要求时，完成约定验证也可标已完成，不能伪称用户已验收。
- 用户反馈未解决时，同事件回到处理中，摘要与最近进展同步反映事实。
- 单凭会话空闲、停止或异常退出不能推断完成；尚未继续执行就不写“正在修复”。
- 状态不是完整工作流引擎，不引入审批流、工时、负责人体系或任务依赖图。

## 6. 项目共享与组件边界

### 6.1 与项目知识库共用项目身份

共用 project_id、工作区路径绑定和解析规则，不各自维护一份项目目录映射；同项目多个路径可关联同一事件。

项目登记和路径解析应作为宿主共享基础能力，不依赖“项目知识库”组件必须开启；关闭任一组件均不能删除共享映射或影响另一组件的数据。

| 能力 | 项目知识库 | 项目事件 |
|---|---|---|
| 内容 | 稳定背景与长期约束 | 动态事项概况和最新进展 |
| 默认读取 | 对应项目自动注入 | 按需调用，不自动注入全部事件 |
| AI 修改 | 长期助理集中维护 | 长期助理与普通助理均可维护 |
| 限制 | 项目知识正文预算 | 每字段一句话、字符硬上限与查询条数 |

事件不占知识正文预算，也不能借事件工具修改知识正文。

### 6.2 组件形态

建议组件 ID 为 project-events，随默认内置组件安装并默认启用，最终命名沿用仓库规范。

开启时声明查询与写入能力，关闭时移除能力和自动维护提示，不删除已有数据；不启动额外常驻服务，不引入新数据库依赖。

能力清单只简短告知“可查询项目近期事件”，事件正文仅在调用后进入当前上下文；不按模型能力换渠道、换模型或隐藏截断。

### 6.3 权限建议

- 长期助理可跨项目查询和维护事件。
- 普通助理和任务会话可查询、维护自己实际工作区绑定项目的事件，不可伪造 project_id 跨项目写入。
- 写操作仍遵守会话实际权限档，read-only 不因组件内置或助理角色而获得写权限。
- 普通会话只关联同项目会话；长期助理关联来源时校验实际相关性，跨项目历史不会因事件工具自动展开。
- 用户通过设置页管理全部登记项目的事件，删除采用确认后删除事件记录，不删除关联会话。

以上“普通助理限定自身项目”为隔离建议，与用户确认的“普通助理也可查询修改”兼容，实施前在权限矩阵中再次核对。

## 7. 建议数据结构与事务

使用 SQLite，复用既有 SQLite 运行机制；建议与项目登记共用项目域数据库，以便外键与事务一致，不在本稿强行固定实际文件路径。

| 表 | 主要字段 |
|---|---|
| project_events | id, project_id, title, summary, status, latest_progress, latest_session_id, latest_message_seq, created_at, updated_at, revision, related_event_id（可选） |
| project_event_sessions | event_id, session_id, linked_at，event_id 与 session_id 联合唯一 |

建议索引为 (project_id, updated_at, id)，按修改时间和 ID 稳定排序，关联表对 session_id 建索引以便查找当前会话已参与的事件。

时间由宿主生成并存 UTC，展示和筛选显式使用时区；revision 用于乐观并发校验，不要求默认列表显示。

更新以 PATCH 语义提交变化字段并携带 expected_revision，避免整体覆盖其他会话刚写的进展；版本冲突拒绝保存，要求重读合并，不能强行覆盖。

文本、状态、关联关系与最近进展来源在同一事务校验和保存；新增会话关联去重追加，重复关联属于无变化，不刷新修改时间。

确有内容、状态或关联变化才更新 updated_at，读取、打开设置页和重复提交相同值均不刷新时间；时间表示事件记录最近被实质修改，不保证就是代码落盘时间。

更新最近进展必须同时明确来源会话或显式无来源，不能留下上一轮错误的 session 指针；summary 可独立更新。

会话若后来被删除，保留事件摘要与关联 ID 的可识别缺失状态，详情提示来源不可用，不能把事件一起级联删除或编造替代来源。

V1 仅保存当前事件状态与最新进展，不新增每轮进展日志或自动摘要历史；通用审计机制可以复用，但不以此承诺历史时间查询。

## 8. 工具建议

组件能力名仅为设计占位，实施时通过现有 component_call 协议暴露，不新增另一套工具路由。

### 8.1 project_events_query

输入：project_id（普通会话可从绑定推导）、from、to、可选关键词和状态、limit、cursor。

- 默认 limit=12，建议单页上限 40，超过上限报参数错误或要求分页，不返回无限条目。
- 默认 updated_at DESC、id DESC；按 (updated_at,id) 游标翻页，同一时间的记录不因简单偏移而轻易重复遗漏。
- 返回事件 ID、标题、状态、摘要、最近进展、修改时间、最近进展会话与可选消息位置、关联会话数量、revision，以及有无下一页。
- 不默认展开全部关联会话 ID，更不读取任何会话正文。
- 查询 project_id 未命中、未绑定或无结果时明确返回对应状态，不回退到其他项目。

### 8.2 project_event_get

按 event_id 查询当前概况并分页列出关联 sessions，提供必要的会话标题与缺失状态，不自动汇总或全文读取关联会话；关联列表默认二十条，可继续翻页。

### 8.3 project_event_create / project_event_update

新建返回 event_id 和 revision，更新接收 expected_revision 及变化字段，关联会话可去重追加；需要移除关联时显式提交并确保最近进展来源仍有效。

普通会话创建前查询自己的关联事件及项目近期列表，同一独立目标继续使用 event_id，不因重开会话而新建。

不对相似标题实施强制去重；若后续发生误建，由助理或用户确认后整理，不在 V1 开发自动合并引擎。

## 9. 时间搜索的准确含义

时间范围按事件 updated_at 筛选，建议区间语义为 from <= updated_at < to，缺省不限制时间；日期输入在界面按选定时区转换，非法范围拒绝查询。

重要边界：工具回答“最新修改时间落在此范围内的事件”，不保证回答“这段时间曾发生过的所有进展”。

例如事件昨天有进展、今天又更新，只保存当前记录时按昨天筛选可能看不到它；界面和能力说明必须说明这一点，不假装拥有历史流水。

“最近十二条”只是单页数量，不代表仅保留十二个事件，也不意味着默认只查最近十二天。

## 10. 维护时机与读取顺序

### 10.1 维护

1. 长期助理或普通助理确定独立目标时，先查已有事件，确需新建再登记。
2. 派发、继续处理或评审时，在任务书携带适用的 project_id 和 event_id，并将新会话追加关联。
3. 只有新结论、验证结果、阻碍、用户反馈或阶段变化等有意义进展才更新，不记录每次工具调用。
4. 接到回报后先读取当前版本，核实新增事实再更新，避免长期助理用旧回报覆盖任务会话较新的状态。
5. 普通会话也能维护事件，但知识库内容仍只能提出修订建议，不能混淆两个组件权限。

V1 使用工具和简短维护指引，不在每次查询时调用模型重新概括全部会话，也不自动扫描所有历史来回填事件；仅有提示词不等于保证每次必登记，后续实际验收应检查漏记情况。

### 10.2 读取

用户问近况 → 查询项目事件 → 直接利用一句话摘要与最近进展回答 → 需要细节先读最近进展会话摘要或指定消息 → 追查过程时再选读其他关联会话。

不因“有三个关联会话”就自动把三个会话全读一遍，不把未读取的原文说成已经核实。

## 11. 设置页

在“项目事件”组件设置中提供项目选择、时间范围、状态与关键词筛选，默认显示最近十二条并支持加载更多。

列表显示标题、状态、摘要、最近进展、修改时间与来源会话入口；详情展开关联会话，并提供编辑、增补关联和确认删除。

编辑时显示字符计数及一句话提示，保留当前 revision，并发冲突时保留用户输入并提示刷新合并；来源会话不可用时给出明确提示。

空项目显示尚无事件，未绑定目录引导先登记项目，组件关闭不删除数据；不另建大型任务看板或长篇日志编辑器。

## 12. 实施边界与验收

实施前先协调仓库写入窗口，从届时最新 dev 开功能分支，复用现有组件、项目映射、会话与 SQLite 机制，不在方案提交时实现功能。

重点验收：

- 同 Bug 多轮派发、返工与评审仍为同一事件，一个会话也可关联多个独立事件。
- 同项目多个路径共享事件，不同项目不串查串写，知识库组件关闭不破坏事件项目解析。
- 默认返回十二条并按修改时间排序，时间边界、时区、同时间排序与分页正确。
- 摘要和最近进展各一句话且分别限长，换行、多句、超长拒写，原记录、时间和版本保持不变。
- 最近进展来源与关联关系一致，来源消息可选，用户更新和缺失会话均有明确表示。
- 普通助理能读写本项目，不能跨项目伪造；只读档拒绝写入。
- 并发冲突不丢失更新，重复读取和无变化保存不刷新修改时间。
- 默认查询不读取会话正文、不展开全部关联 ID、不自动注入事件列表、不自动切换模型或渠道。
- 设置页可查可改，字符限制与工具保持一致，关闭组件不丢数据。

本轮交付仅为本文与配套知识库文档归档，不修改功能代码、运行配置或实际项目数据。
