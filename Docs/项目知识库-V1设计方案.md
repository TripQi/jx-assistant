# 项目知识库 V1 设计方案

- 初稿日期：2026-11-14；本次修订：2026-11-15。
- 状态：产品口径已确认的实施基线，尚未实现；本轮只修订文档，不修改功能代码或运行数据。
- 配套方案：[项目事件 V1 设计方案](项目事件-V1设计方案.md)。
- 本文与配套文档为唯一有效基线，取代原记忆分层待办和旧记忆改造 v1.1 草稿中的冲突设计；接口名、表字段名与模块文件名仍为实现建议，不改变已确认的行为要求。

## 1. 目标与信息边界【已确认】

将用户记忆与项目知识分开，解决项目背景混入全局记忆及不同项目知识串味的问题。

1. 用户记忆保持所有会话自动注入，只记录用户身份、习惯、喜好和跨项目偏好，不再记录项目背景。
2. 新增独立组件“项目知识库”，建议 ID 为 `project-knowledge`，使用现有 `jx.db` 分表存储。
3. 项目拥有稳定 ID，一个项目可绑定多个工作区，例如同项目的前端、后端或固件、上位机目录。
4. 长期助理按需查询、集中维护知识；工作会话按自己实际工作区自动加载对应项目知识，不能直接修改知识正文。
5. 知识只保存当前正文、递增版本号和更新时间，不保留历史正文，不提供历史恢复。
6. 每项目默认 4000 预算单元，仅用户在设置页调整上限；80% 预警，恰好 100% 强提醒，超限拒绝保存并指导压缩，不截断。
7. 项目日常使用归档；永久删除只允许用户在设置页确认执行，不删除来源会话、代码或工作区文件。
8. 动态近况交给独立“项目事件”组件，不挤入知识正文；不设“重要决策”栏目，设计原因就近记录在代码或模块说明中。

定位：**项目知识库是一份短而可靠的“项目入场须知”，不是开发日志、历史决策档案或任务进度表。**

### 1.1 信息分工

| 信息 | 存放位置 |
|---|---|
| 用户身份、沟通喜好、跨项目行为偏好 | 用户记忆，全会话生效 |
| 项目用途、组成与必要背景 | 项目知识库 |
| 当前长期有效的项目约束 | 项目知识库 |
| 某段实现为什么采用特殊做法 | 邻近代码注释或模块说明 |
| 独立目标的概况与最近进展 | 项目事件，一句话字段，按需查询 |
| 临时排错、执行细节与待办 | 会话、回执、待办 |
| 如何记录设计理由 | 后续独立 skill |

换一个项目仍成立的要求才可能属于用户偏好；只对某个项目成立的背景或约束归该项目。秘密和凭据不得写入上述知识或事件正文。

### 1.2 知识正文组织

```markdown
## 项目背景
- 项目用途、必要背景与主要组成。
- 各绑定目录之间的关系。

## 当前有效约束
### 全项目
- 所有绑定目录共同遵守的约束。

### 模块名称（按需要自定义）
- 仅适用于该模块或目录的约束。
```

分区名称由实际项目决定，“前端/后端”只是例子；不开发动态模板、多层知识继承或独立条目分类系统。

不收录琐碎决策、流水账、长篇推演、任务进度、未经验证的推测或随时可从代码查到的细节。若决策产生持续约束，只记录“现在必须遵守什么”，不记录决策史。

知识库不替代根目录 `AGENT.md` / `AGENTS.md`、`README` 等规范；仍须按现有要求阅读，冲突时核实并提出修订，不静默覆盖或编造优先级。

## 2. 项目身份、登记与路径解析【已确认】

### 2.1 共享身份与管理入口

项目 ID 独立于路径，搬迁目录只调整绑定，不创建新项目或丢失知识；不按目录同名、Git 远程相似或内容相似自动合并。

项目新建、名称与绑定管理、归档、恢复使用、永久删除均由用户在设置页执行；AI 工具第一版不提供这些结构管理能力。每项目预算上限也仅由用户调整。

未登记项目时，助理明确说明未登记并引导到设置页；当前任务可以继续，但不擅自建项目，不把知识或事件写入其他项目，也不新增收件箱。

两个组件共用宿主项目登记与解析能力，不分别登记项目，也不要求知识库组件开启才能使用项目事件。

### 2.2 路径匹配

- 按平台规则规范化绝对路径、分隔符、末尾分隔符和大小写比较方式。
- 绑定根目录覆盖其子目录，按目录边界匹配，`app` 不匹配 `app-old`。
- 嵌套绑定使用最长路径优先，界面明确展示实际归属；更具体的已归档绑定不回退到外层项目。
- 同一规范化绑定只能归属一个项目，数据库加 `UNIQUE(workspace_kind, workspace_key)`。
- 本地与远程使用不同命名空间，远程身份包含连接目标和规范化路径，不只按路径字符串匹配。
- 离线、目录暂不存在时保留登记；符号链接、junction 不自动推断归属，需要时用户显式绑定。
- 目录重新绑定不迁移旧事件，事件原有 `project_id` 不变；普通会话之后按当前绑定取得访问资格，历史来源关系不会随当前路径映射改写。
- 未命中时不注入任何项目知识，不回退到其他项目。

### 2.3 宿主归属【实现建议】

建议 `projects.go` 承担共享项目服务、工作区解析和用户管理接口，`store_projects.go` 承担 `Store` 上的项目数据访问，两个组件调用同一服务；不为每个组件重复造路径映射。

该职责属于宿主共享基础设施，关闭任一组件不删除、不停用共享绑定；实际文件拆分实施时遵守现有结构，不为命名额外增加抽象层。

## 3. 项目生命周期与组件开关【已确认】

| 操作/状态 | 知识库行为 | 项目事件行为 |
|---|---|---|
| 使用中 | 正常查询、维护及项目会话自动注入 | 正常查询维护 |
| 已归档 | 停止自动注入，保留只读查询，可恢复使用 | 保留只读查询，禁止新增修改 |
| 关闭知识库组件 | 停止本组件能力与注入，不删除数据 | 不受影响 |
| 关闭事件组件 | 不受影响 | 停止事件能力和维护提示，不删除数据 |
| 永久删除项目 | 删除项目绑定和知识 | 删除该项目事件及关联行，不删除会话本身 |

归档不是停止任务，不中断正在运行的会话；下一次写入校验发现已归档则拒绝，提示先由用户恢复项目。归档项目不自动回退到其他项目，允许有权限的会话显式查询并标注已归档；只读限制针对内容和关联维护，不阻止用户执行恢复或经确认的永久删除。

永久删除仅用户在设置页确认后执行，事务内删除项目、绑定、知识、事件及事件关联行；不删除来源 sessions、消息、代码、附件或工作区文件。删除后旧 ID 的请求明确失败，不凭同名项目自动恢复。

组件开关按既有全局/会话覆盖机制生效，不等于项目归档；各组件关闭后对自己原有有效知识的撤销在后续请求体现。

## 4. 单库存储与当前版本【已确认，表名为建议】

所有项目数据进入当前实例 `dataDir` 下既有 `jx.db`，遵守“分表不分库”，不另建知识库或项目域数据库文件；复用现有 SQLite 驱动、连接和事务，不增加数据库依赖。

结构升级追加到 `storeMigrations`，由 `schema_migration` 账本及 checksum 管理，不修改已应用迁移；不要混用 `migrations.go` 的程序目录一次性资源迁移机制。

项目登记属于实例域：不同 `dataDir` 的实例各自登记，不自动跨实例同步；用户可导入导出正文，但来源会话不因此自动搬迁。

| 表 | 主要字段 | 职责 |
|---|---|---|
| `projects` | `id`, `name`, `archived`, `created_at`, `updated_at` | 共享项目身份与生命周期 |
| `project_workspaces` | `project_id`, `workspace_kind`, `workspace_key`, `display_path` | 多路径绑定，全局唯一约束见 §2.2 |
| `project_knowledge` | `project_id`（主键）, `content`, `revision`, `updated_at`, `budget_limit` | 每项目一份当前正文与额度 |

项目外键删除绑定、知识及事件；事件删除进一步清理关联行，绝不由项目删除级联到 sessions。

### 4.1 当前版本号，不是历史版本库

- `revision` 为当前记录的单调递增整数，用于并发校验与注入新鲜度，不代表保存旧正文。
- 只保留当前正文，不创建知识历史表，不提供历史列表、历史恢复或更新前正文备份功能。
- 成功覆盖后组件自身不能恢复旧内容，设置页明确提示；不能把会话历史当作可靠备份承诺。
- 更新带 `expected_revision`，事务内核对当前版本、项目状态、权限与预算，冲突拒绝并指导重读后合并。
- 有效正文或预算上限变化才更新知识版本和时间；重复保存相同值不刷新，失败不改正文、版本和时间。
- 修改预算与正文共用版本校验，避免用户调整额度与 AI 更新正文互相覆盖；名称/绑定等项目元数据不伪装为正文修改，但同样影响后续环境组装。
- 时间由宿主生成，存 UTC，展示带时区；不信任模型传入的版本新值、更新时间或预算用量。

## 5. 能力、角色与维护流程【已确认】

### 5.1 模式映射与访问资格

| 文档角色/模式 | 知识读取 | 知识写入 |
|---|---|---|
| 长期助理 `assistant` | 任一已登记项目，按需查询 | 集中维护使用中项目 |
| 工作会话 `task / office / coding / beginner-coding / skill-create` | 自动加载及查询自身绑定项目 | 不允许，只能提建议 |
| 只读答疑 `aux` | 只读自身绑定项目 | 不允许 |
| 用户设置页 | 查看全部登记项目 | 编辑正文、额度与项目管理 |

“子会话”是来源/层级，不是额外授权角色，仍以其 mode 与实际目标工作区解析资格。用户记忆保持所有会话注入，不因本方案改变拟人化设置及现有会话覆盖机制。

后端同时校验模式、实际权限档、组件开关、项目状态和项目归属；不能仅依赖提示词、调用方 project_id 或父会话身份。

### 5.2 统一 AI 入口与公共权限依赖

两个新组件的 AI 查询、写入统一经 `component_call`，长期助理也走同一入口，不再新增另一套 AI `call_api` 写通道。清单需显式允许 `assistant`，不能照抄用户记忆清单而漏掉长期助理。

公共组件写权限门由独立任务处理，本方案不将其误称为原本已有的检查；实施前核对该依赖已落地，所有声明 `Writes` 的能力在 read-only 和计划模式下拒绝执行，workspace-write/full 仍须满足角色及项目约束，缺少合法会话上下文不得放行。

设置页用户操作与 AI 工具区分身份，但复用同一业务校验、预算计算和事务服务；不让 AI 借设置页接口绕过角色权限。本方案不借新功能扩大用户记忆写权限，公共门修复产生的统一收紧另行验收。

建议能力：

- `project_list(query?, include_archived?)`：长期助理发现项目，返回 ID、名称、路径和归档状态，不返回全部正文；普通模式如开放此能力，只返回自身项目。
- `project_knowledge_get(project_id?, workspace?)`：返回当前正文、revision、更新时间、额度与状态；普通会话只能读自身项目。
- `project_knowledge_update(project_id, expected_revision, content)`：仅 `assistant` 可修改使用中项目的正文，不能修改额度、绑定或归档状态。

自动注入不依赖主动查询；长期助理问及某项目时先定位并查询最新知识，指代不明先查列表，不凭相似名称认定。

### 5.3 保存及建议反馈

长期助理先读当前正文与版本，根据核实事实整理，再带 `expected_revision` 提交；成功返回新版本、时间、用量与预警，冲突或超限返回可执行的修正指引，不盲目重试旧正文。

任务会话仅在需要时在回执附上项目、所依据版本、过期/遗漏/冲突点、建议内容及事实依据；无需更新不填空模板。长期助理读取回报时须检查有无知识修订建议，核实后决定是否采纳，不能直接照搬猜测。

用户直接开启的普通会话或答疑会话没有任务回执链时，在当前对话向用户说明，由用户或长期助理处理。V1 无持久化收件箱和建议队列，漏看风险由人工流程承担，不宣称保证送达或必定采纳。

## 6. 自动注入、撤销与压缩一致性【已确认】

### 6.1 格式与范围

```text
# 项目知识库（仅适用于下述项目）
- 项目：示例项目 / project-example
- 当前工作区：workspace/example/module（示意）
- 知识版本：v7
- 更新时间：2026-11-15T06:00:00Z
- 预算：2400 / 4000 单元（60%）
- 有效性：以当前版本为准，历史快照或摘要中的旧约束可能已失效，冲突须核实。

## 项目背景
……
## 当前有效约束
……
```

示例仅演示格式，默认额度 4000 已确认，具体用量、项目与时间均为虚构。正文完整注入，不隐藏截断；格式化块带版本号、更新时间与用量，用户可在环境内容中查看。

长期助理按需查询，不自动加载所有项目正文；其余模式在每次请求的环境组装中按实际工作区解析，只生成本项目的有效知识块，不能把其他项目先广播再撤销。

### 6.2 刷新与撤销

复用现有环境快照和差分，按会话生成，无需唤醒空闲会话或新建广播系统；更新在下一次模型请求前生效，不中断正在输出的模型响应。

首次命中注入完整块，正文更新明确旧版本被替代；工作区切换、解绑、项目归档/删除或组件关闭时，明确旧块不再适用，再按新状态组装。多行差分不得残留旧约束仍生效的歧义，必要时把知识块作为整体替换单元，遵守既有消息类型语义。

压缩后的环境基线重新包含当前有效知识；摘要指引尽量不重复知识正文，确需提及时保留项目和来源版本。当前有效知识优先于旧快照或摘要中的约束；旧项目已撤销时也不能凭摘要恢复其效力。

历史原文不重写，模型已读信息无法真正抹掉；验收必须覆盖压缩前后更新、归档及切换项目，不能只测试环境块自身的差分。

### 6.3 派发隔离

- 归属以目标工作区为准，不无条件继承父项目。
- 同项目按目标加载，不重复叠加多份知识快照。
- 跨项目派发使用自足任务书，不提供整段父历史继承，不能指望语义过滤可靠剔除其他项目。
- 用户记忆仍跨会话注入；模型手工转述任务背景同样须遵守项目边界，不宣称绝对隔离。
- 已有会话切项目只撤销旧知识效力，建议跨项目新开会话，不把环境更新宣传成历史擦除。

正文超出实际模型上下文能力时明确报错并指导整理内容或由用户调整配置，不静默裁剪、不回落或切换模型/渠道。

## 7. 预算计算与超限行为【已确认】

```text
预算单元 = 2 × CJK 字符数 + ceil(非 CJK 字符数 / 4)
```

### 7.1 计数口径

新增专用预算函数，不将 token 估算函数当作已有实现；按 Unicode code point 统计，不按 UTF-8 字节或 UTF-16 code unit 统计。

CJK 判定固定使用 Go 标准库 Unicode 脚本分类 `Han`、`Hiragana`、`Katakana`、`Hangul`，不自行扩大为全部东亚字符；其他脚本、数字、空白、标点及归属 Common/Inherited 的字符均按非 CJK 计算。全文非 CJK 总数只执行一次向上取整，不逐行取整。

正文标题、标点、空白均计入；项目名、注入外壳、版本与时间不占正文额度，但仍有上下文开销。界面实时预览与后端采用一致分类规则，后端是权威，不依赖浏览器 Unicode 版本恰好相同；必要时共享对应范围表或由宿主计算。

新项目默认 4000 单元，每项目上限仅用户在设置页改为合法正整数，AI 不得为保存成功自行扩容。降低至小于当前用量时拒绝配置，提示先整理正文；知识本身不设自动压缩过程。

### 7.2 阈值与失败原子性

| 用量 | 保存行为 | 返回与修正指引 |
|---|---|---|
| `< 80%` | 正常保存 | 返回已用/上限 |
| `>= 80%` 且 `< 100%` | 正常保存 | 已达到容量 80%，请删除或压缩过期约束 |
| `= 100%` | 允许保存 | 已达到 100% 硬阈值，请立即重构知识库 |
| `> 100%` | 拒绝本次保存 | 返回实际用量、上限及超出量，要求精简后重试；确需扩容由用户在设置页调整 |

比较使用整数关系，不按显示百分比四舍五入判断。拒写、版本冲突或其他失败均保留当前完整正文、版本和时间，不产生半次保存；无静默截断、隐藏裁剪或旧正文历史备份。

到达上限仍允许读取和精简删除正文内容；工具、设置页、导入共用校验，归档项目仍不得写。Markdown 导出导入用于用户阅读、交换和手动备份，不等于组件提供版本恢复。

## 8. 设置页与用户操作

项目管理入口提供新建、名称、绑定路径、解析归属、使用中/已归档、恢复和永久删除，两个组件复用同一登记服务。

知识组件编辑页展示当前正文、revision、更新时间、预算用量和阈值，允许用户修改每项目上限，提供保存、取消与 Markdown 导入导出；不显示历史版本或恢复按钮。

保存前提示覆盖后无法由组件恢复，冲突时保留用户草稿并要求刷新合并。导入超限拒绝并给出精简指引，不截断；不建议通过外部 SQLite 编辑器在线写库，不能承诺绕过服务后仍自动维护版本及预算。

## 9. 旧方案、迁移与 skill 边界

### 9.1 旧稿取舍

旧 v1.1 草稿作废，以下不再沿用：关联组层、持久化修订收件箱、100% 自动/强制压缩、Markdown 作为知识存储、逐派发工作日志、项目摘要 2000/每轮合计 5000 的双重额度。

跨项目用户偏好归用户记忆；多个项目共享的业务规则 V1 不单建关联层，不将同项目正文分区冒充跨项目共享。动态记录由项目事件按独立目标组织，不是逐派发日志。

### 9.2 迁移

现有用户记忆不自动清空或猜归属；先向用户列出项目专属内容，确认绑定，写入并验证项目知识后，再移除全局用户记忆中的对应片段。维护提示词去掉“项目背景写入用户记忆”的引导。

未登记或组件关闭时保留原有对话功能，旧历史消息不重写；不同实例不自动共享登记和迁移结果。

### 9.3 设计理由 skill

后续独立制定：解释非显然的人的设计意图，就近记录，不复述代码、不编造历史；逻辑变更同步维护注释，重要可验证约束配测试，并明确 skill 发现与加载方式。本组件 V1 不实施该 skill。

## 10. 实施顺序与非目标

实施前协调写入窗口，从届时最新 `dev` 建功能分支；本轮只提交文档，不切分支、不编译重启。

1. 核对公共组件权限门与既有模式、环境组装、迁移机制，明确依赖已满足。
2. 实现共享项目服务、路径解析、生命周期与单库追加迁移。
3. 新增预算函数、当前知识存储及事务版本校验，不实现历史表。
4. 接入组件能力、角色校验和设置页，复用业务服务完成导入导出。
5. 接入按会话注入、撤销、压缩一致性与派发隔离。
6. 补维护指引和针对性测试，按用户约定试编试用，确认无运行任务后验证，满意再合入 `dev`。
7. 用户确认后执行混合记忆拆分迁移。

V1 不做向量检索、RAG、自动总结历史、自动写知识、多层继承、分支知识库、历史正文恢复、决策日志、建议队列、多实例同步或后台自动压缩。

## 11. 验收清单

- 两组件共用项目，关闭任一组件不破坏另一组件解析；新实例无旧实例项目数据。
- 路径大小写、末尾分隔符、目录边界、嵌套最长匹配、本地/远程身份及唯一约束正确。
- 未登记引导设置页，不擅自登记或回退；重绑目录不迁移旧事件。
- `assistant` 可跨项目查写知识，五种工作模式和 `aux` 均不能写；普通模式不能伪造跨项目查询。
- 公共 `Writes` 门在 read-only、计划模式及缺失会话上下文时拒绝；workspace-write/full 仍受角色与项目状态约束。
- 每项目默认 4000，额度只由用户调整；预算覆盖四类脚本、非 BMP 汉字、标点/空白与全文一次取整。
- 80%、恰好 100%、超限、非法额度及降额低于用量行为正确；拒写给出实际用量和可执行修正指引，无截断。
- 更新带 revision 防覆盖，失败及无变化保存不刷新；只有当前正文，覆盖后无历史恢复入口。
- 注入带正确版本/时间/预算，无关项目不收到正文；更新及撤销在下一次请求生效。
- 知识更新前后压缩、切工作区、解绑、归档、删除、关闭组件均不让旧约束恢复效力。
- 归档停止注入并只读可查，恢复后正常；永久删除清理项目数据但不删 sessions、代码和文件。
- 回执建议和直接会话建议渠道明确，长期助理检查建议；迁移经用户确认，不自动清空记忆。
- 设置页编辑、导入导出及草稿冲突提示正确，不提供历史恢复、不触发模型/渠道切换。
