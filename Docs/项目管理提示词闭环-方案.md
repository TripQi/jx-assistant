# 项目管理提示词闭环方案（供拍板）

- 状态：已实施（功能分支 `feat/project-management-prompt-loop`，实施记录见文末）；本文保留为拍板定稿。
- 基线：`dev@99158ff4`（2026-11-17）；项目知识 revision 2（2026-11-16）。
- 目标：让长期助理集中维护项目背景知识与持续项目事件，让工作任务把关键新事实回报给经理；不把执行进度写进知识库。

## 建议拍板

**采用“长期助理统筹、项目知识存稳定约束、项目事件存关键进展、工作任务只回报候选事实”的闭环；只补长期助理与执行模式提示词、两份组件能力说明，不加工具、数据库、强制流程或注入核对。**

## 当前实现核对

- `agent.go` 的 `systemPrompt` 以模式选基础提示词；`data/prompts/<mode>.md` 可覆盖该模式基础正文，但产品附加段仍由代码拼接。长期助理另拼 `managerCoordPrompt`，此处在覆盖后仍生效，适合作为核心闭环落点；五种执行模式共用文件及子对话附加段。组件能力块只列当前启用且当前模式可用的能力，可承载与能力同生命周期的短规则。提示词是请求稳定前缀，修改会改变前缀指纹。
- `tools.go:toolsFor` 的长期助理有编排与只读工具，没有 `dispatch_sub`；执行模式有 `dispatch_sub`、`request_manager` 和统一 `component_call`。提示词可指路，不能取代工具权限。
- 组件能力说明来自启用组件的 manifest，经 `componentCapabilityBlock` 写进环境快照；组件开关即时改变可见能力块。`project-knowledge` 当前知识读取可见于长期助理/工作/aux，知识更新仅 assistant；项目知识正文始终仅长期助理可写。`project-events` 查询可见这些模式，事件写能力可见 assistant 与五种执行模式，不含 aux；事件现有写权保持不变。
- 工作任务及 aux 的项目知识会按工作区自动注入环境快照（已验证），故不增加“每次核对注入”步骤；提示仅说明注入内容是约束依据，需核对项目身份/版本或存在冲突时再查。
- 根目录 `数字经理系统提示词.md` 是人工维护的长期助理提示词镜像，当前无代码引用，不是运行入口。若方案实施涉及经理提示词，镜像应同步，并标注真实运行附加来源为 `agent.go` 的 `managerCoordPrompt`（及按启用能力条件出现的组件能力说明），避免误认为镜像全文就是运行时提示词。

## 最小提示词落点

| 落点 | 只增加的规则 |
|---|---|
| `agent.go`：`managerCoordPrompt`（在 `assistantPrompt`/`data/prompts/assistant.md` 覆盖后仍追加） | 仅当环境快照的组件能力块列出对应项目能力时，才要求读取/维护该类项目数据；项目知识与事件分别按各自能力是否可用条件化。知识仅经理写，事件由经理默认写。任务书携带已有项目/目标 ID，并提醒遵循可用的项目知识约束。收到顶层任务最终答复时，按证据与最新 revision 核实候选事实；去重，晚到旧事实不倒退当前概况。无更新不要求报告；有实质写入或写入失败时简短说明，成功回执即确认，不例行重复读取。 |
| `agent.go`：执行模式共用短附加段（新增常量，拼入现有五模式分支） | 仅在环境快照列出相应组件能力时遵循该能力的项目维护要求。项目知识自动注入时遵循约束；仅项目/版本不明或冲突才查证。任务结束有稳定知识修订建议或事件关键事实时，写在最终答复，随现有顶层派发回报交经理；不另用 `request_manager` 重复上报。普通任务只建议知识修订，知识正文始终不由工作会话写；经理明确委托时仅可代写项目事件并回报记录 ID。子对话向父任务最终汇总；仅需及时协调时才用 `request_manager`。用户直接开的任务没有经理回报链时向当前用户反馈，不声称已送达经理。无候选事实不填模板；任务完成不等于用户验收。 |
| `组件/project-knowledge/manifest.json` | 精炼能力说明：只维护必要背景和持续有效约束；交付/修复/提交/验收进展归项目事件。明确知识正文只由长期助理写。能力块随知识组件启用而出现；关闭时不要求调用知识能力。 |
| `组件/project-events/manifest.json` | 精炼能力说明：项目进展问题按项目/目标查事件；新进展记有依据的关键事实，任务完成不代表验收；派发沿用目标，不重复建事件。事件写权不变，能力块随事件组件启用而出现；关闭时不要求调用事件能力。 |

经理核心规则放在覆盖后仍拼接的 `managerCoordPrompt`；组件特定提示仅放各自动态能力说明，组件关闭或模式无该能力时规则随之消失。无需另设静态的、会要求调用已关闭组件的项目提示段。执行模式共用规则仅通过现有附加段拼一次，不放进可覆盖基础正文。

**长期助理（建议并入覆盖后仍追加的 `managerCoordPrompt`）：**

> 仅当环境快照列出相应项目组件能力时，按其能力管理该类数据；组件关闭或模式无该能力时不要求调用。知识正文始终仅由长期助理维护；项目知识只存必要背景与持续有效约束，交付、修复、提交、验证和验收等进度记入项目事件。用户问进展先查可用的相关事件；安排项目工作前读可用的最新知识及相关事件，沿用已有 `project_id`/`event_id`，派发时提醒遵循可用的项目知识约束。任务结果返回后核实有依据的知识建议与事件事实，按最新 revision 写知识、检查事件重复及事实时间；晚到旧事实不倒退当前概况。任务会话仅在明确委托时可代写事件，不得写知识。顶层工作任务的候选事实随最终答复回传，不重复调用 `request_manager`；仅需及时协调时使用该通道。无更新不要求填模板；有实质写入或写入失败时简短告知，成功回执即确认，必要时再核验。

**工作任务（建议作为一个共用短段追加到五种执行模式）：**

> 仅在环境快照列出相应项目组件能力时遵循其维护要求；组件关闭或当前模式无该能力时不要求调用。项目知识自动注入时遵循约束；仅项目/版本不明或冲突时再查证。结束时分别判断有无稳定知识修订建议、事件关键事实：有则写入最终答复，随现有顶层派发回报交经理；一般只建议知识变更，知识正文始终仅长期助理可写。明确委托代写只限项目事件，并回报记录 ID；子对话向父任务最终汇总，不越级重复维护。`request_manager` 仅用于需及时协调，不用于重复报告常规收尾。没有经理回报链时向当前用户反馈，不声称已通知经理。无候选不填空模板；任务完成不等于用户验收。

**动态组件能力说明（仅组件启用且能力可用时出现）：**

- 知识：`只存必要项目背景与持续有效约束；交付、修复、提交、验证和验收进度归项目事件。知识正文仅长期助理可写。维护前核实最新 revision 与依据。`
- 事件：`项目进展问题按 project_id/event_id 查相关目标；只记有依据且不重复的关键事实，按事实时间判断，任务完成不等于用户验收。`

## 会话边界与可靠性

| 会话 | 口径 |
|---|---|
| 长期助理 `assistant` | 唯一项目知识正文写入者及事件统筹者；项目闭环放在覆盖后仍追加的 `managerCoordPrompt`，知识/事件的具体维护指引只随各自启用能力出现。 |
| 顶层工作会话（五种执行模式） | 可沿用现有事件写权；默认只建议知识修订，绝不写知识正文。完成后候选事实随最终答复进入现有派发回报；经理明确委托时可代写事件并回报记录 ID。 |
| 子对话（`dispatch_sub`） | 不越级联系经理或独立维护项目数据；将候选事实交父任务最终汇总，由父任务决定是否并入顶层回报。 |
| `aux` | 只读答疑；可按需查询，不写事件/知识，不派发、不承担回报链。 |

写入前按需读取当前 revision 与依据；事件去重并按事实时间处理，晚到旧事实不得倒退当前概况。写入成功以工具回执为确认，不要求例行重复读取；遇冲突、异常或结果不明时再核验。对用户不强制每轮列知识/事件写入状态：没有实质变化不报空栏，有实际写入或写入失败时简短说明，并与任务结果分别表述。

## 最小验证（实施时）

1. 静态核对 `systemPrompt` 最终拼装：长期助理使用 `managerCoordPrompt` 的覆盖后附加落点；五种执行模式共用附加段；核验 `data/prompts/<mode>.md` 覆盖后仍保留附加规则，且 aux 不收到写入要求。
2. 用现有 `toolsFor` / 组件环境快照检查：执行模式仍有 `request_manager` 与 `dispatch_sub`；知识更新仍仅 assistant；事件查询/写可见范围不变；关闭组件或模式无对应能力时，其动态维护提示同时消失；无新增工具或数据 schema。
3. 提示词样例验收：进度查询先查事件；派发带项目/事件 ID 与一句知识约束提醒；常规结果随最终答复回报，不重复求助；知识建议不越权写入；事件委托代写回传 ID；子对话只汇总给父任务；直接任务不假称已通知经理；无更新不填空模板；晚到旧回报不回退；不伪称验收；写入失败独立表达。
4. 只跑变更直接相关的既有定向测试；不编译、不重启、不跑全量测试。提示词文案的小改不需要额外端到端或运行实例检查。

## 范围外

不新增组件工具、数据库字段、流程引擎或强制每轮检查；不改变现有事件写权；不补历史事件、不扩充知识库；不改工作区知识自动注入。人工镜像如随实施方案变更须同步并标注运行时附加来源。本文只落方案分支，不合并、不推送。
