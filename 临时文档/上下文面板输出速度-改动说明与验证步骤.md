# 上下文面板显示模型输出速度（吐字速度）- 改动说明与验证步骤

## 功能

上下文用量圆环的悬停卡片（Token 用量块）新增「输出速度」一行：

```
输出速度  50.0 tok/s（210 tok / 4.2s）
```

- **口径**：最近一次有效输出。分子 = 厂家流尾 usage 报的 `completion_tokens`（`stream_options.include_usage` 早已开启），分母 = 输出窗口时长——首个输出事件（正文或思考增量）到末个输出事件之间，不含首字前的排队等待（整次调用耗时混着等待，直接除会明显拉低速度）。
- **落库方式**：不加表不加列。引擎每次模型调用本来就在 messages 表落一条 `kind=audit`、`type=call` 的调用审计行（耗时/字数/缓存命中都在），本次只是往这条行里加 `outMs` 字段——**每次输出各存一条**，「最近一次」由 `/api/sessions/{id}/context` 查询时倒序取得。历史全保留，以后想看趋势数据也是现成的。
- **无数据不显示**：网关不报 usage（无 completion_tokens）、调用失败、窗口 <100ms（瞬发完成）、侧路摘要调用（scope=summarize）、旧格式行（无 outMs）都跳过；全部跳过时前端不渲染这一行。

## 改动文件

| 文件 | 改动 |
|---|---|
| `agent.go` | 主循环 OnText/OnReasoning 回调记 firstOut/lastOut（重试每 attempt 重置）；RecordCall 调用处传 outMs |
| `contextengine.go` | RecordCall 签名加 outMs；auditRow 加 `OutMs` 字段（导出时间线顺带可见） |
| `context.go` | ctxStats 加 `speed` 块（tokPerSec/tokens/ms）；contextStats 倒序找最近一条有效 audit 行计算 |
| `web/app-chat.js` | renderCtxTip 在「输出」行后追加「输出速度」行（有数据才显示） |
| `context_speed_test.go` | 单测：正常计算、取最近一次、跳过失败/无 usage/窗口过短/侧路/旧行 |

## 验证（已做）

1. `go build` 通过；`go test -run 'TestParseSSE|TestUsage|TestCache|TestContextStatsSpeed' .` 全过。
2. 隔离实例实跑（`-config` 指向 .jxai/tmp 下独立库，mock 提供方）：mock 最后一步 audit 行落 `outMs=241`，与 mock 分段输出节奏（3×80ms 间隔）吻合；工具调用步不落 outMs；mock 无 usage 时 speed 为 0、前端不显示该行、不崩。
3. 向该库补插一条带 usage 的 audit 行（210 tok / 4200ms）后：API 返回 `speed: {tokPerSec: 50, tokens: 210, ms: 4200}`；页面悬停卡片渲染「输出速度 50.0 tok/s（210 tok / 4.2s）」（截图确认）。

## 真实模型下怎么看

升级后随便发一条消息，等回复完成，悬停输入区左侧的上下文圆环即可。旧会话（升级前的输出）没有 outMs 数据，从升级后的第一次输出起才有。
