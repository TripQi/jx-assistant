# 右栏子对话直接发消息——改动说明与验证步骤

## 背景与目标

原行为：右侧栏「子对话」视图没选中子对话时，在右栏输入框发消息会被拦下——
弹出顶部下拉并提示「先选择或新建一个子对话」，消息发不出去。

目标：右栏像主对话的「新对话页」一样，打开就能直接打字发消息。采用与主对话
首页相同的**懒创建**语义：发出第一条消息才真正建子对话（不在打开右栏时就
预建，避免留下一堆空会话）。

## 改动点（web/app-chat.js、web/app-right.js）

1. **prepareSend 懒创建**（app-chat.js）：右栏没选中子对话时不再弹下拉拦下，
   改为 `await newAuxChat()` 自动新建（继承主对话上下文）并就地打开，消息照发；
   无主对话可挂靠或创建失败时由 newAuxChat 就地提示，输入内容保留、本轮中止。
2. **newAuxChat 返回结果**（app-right.js）：返回创建的会话（失败/无父为 null），
   供发送路径判断；首页态（无主对话）由静默 return 改为输入区提示
   「子对话挂在当前对话名下；先打开一个对话」（2.5 秒自动消失）。
3. **空态引导**（app-right.js）：subClearCurrent 的空态文案改为「在下方输入框
   直接发消息，会自动新建子对话…」；下拉空列表文案同步。
4. **placeholder 两态切换**（app-right.js）：新增 `setSubPlaceholder()`——没选中
   子对话时输入框提示「发消息自动新建子对话…」，进入子对话后恢复
   「向子对话发消息…」。正在发送（runHintOn 已记 idlePh 基线）时同步换基线，
   避免流式结束 runHintOff 把旧文案恢复回来。

## 验证步骤（已实测通过，2026-10-19）

隔离目录起 `-webdir web` 开发模式实例，浏览器实测：

1. 空库首页发消息 → 主对话懒创建正常（回归确认，未受影响）。
2. 展开右栏「子对话」→ 空态显示新文案，placeholder＝「发消息自动新建子对话…」。
3. 右栏直接输入「请只回复：收到」点发送 → 自动新建子对话（挂在主对话名下、
   继承段「来自主对话」折叠条正常渲染）、消息发出、模型回复完成；
   placeholder 恢复「向子对话发消息…」、输入框清空。
4. 再发第二条 → 仍发到当前子对话，没有新建第二个。
5. 回首页（无主对话）在右栏发消息 → 提示「子对话挂在当前对话名下；先打开
   一个对话」，不建会话、输入内容保留。

验证后清理：测试实例已停，webtest 临时目录与测试 exe 已删除。
