# 右栏文件工具与文件改动行点击 - 改动说明与验证步骤

> 2026-10-15 · 前端改动（`web/` 三文件，后端零改动） · 构建方式：`go build`（前端经 go:embed 内嵌，替换正在运行的 exe 后生效）

## 一、做了什么

1. **新增右侧栏「文件」页签（文件工具 / diff 查看器）**：展示一个文本文件的**完整内容**，其中本次改动的部分着色——删除的行红色、新增的行绿色、未改动区域正常显示。不是折叠片段视图，是整文件展开、改动处着色。
2. **「文件改动」面板文件行的点击行为改造**：
   - 旧行为：整行点击 = 向下展开该文件的历史版本列表（与「历史版本」按钮同效）。
   - 新行为：**整行点击 = 在右侧栏打开文件工具**，查看本次改动（本批最早快照的"改动前内容" vs 文件当前内容）的整文件红绿对比；**只有行内那个「历史版本」按钮**才就地展开/收起历史版本列表，展开后的既有行为（查看内容 / 恢复到此版本前）原样保留。
   - 悬停文案相应区分：行提示「在右侧栏查看本次改动：整文件红绿对比…」，按钮提示「展开/收起这个文件的历史版本列表…」。
3. 面板标题行（「文件改动 · 修改 N · 新增 M」折叠条）**保持原有折叠功能不变**——它管整块清单的展开收起，不指向任何单一文件，不属于本次调整范围。

## 二、实现方式

### 数据与口径（零新增后端接口）

一行代表一个文件在本回合的全部改动，「本次改动」的 diff 两侧取：

- **旧侧** = 该文件本批（这一回合）**最早一条快照**的"改动前正文"（checkpoint 语义即改动前内容）；
- **新侧** = 文件**当前内容**。

这一对正好是该行「撤回」会在其间恢复的两个状态，口径自洽。数据一次请求拿全：复用既有 `GET /api/sessions/{id}/file-version?path=&id=`（server.go `handleFileVersion`），响应同时携带版本正文与 `current`（当前内容，含 exists/binary/truncated 标记）。

### diff 算法（前端，`web/app-chat.js` 的 `fdiffSplitLines` / `fdiffAlign`，约 1498–1545 行）

行级 LCS：先**修剪公共前后缀**，剩余段做经典 **LCS 动态规划**（`Int32Array` 全表）+ 回溯，得到保序的 删除/新增/未变 行序列。选择它而非 Myers 的理由：

- 有「公共前后缀修剪 + 规模钳制」保护后，剩余段被限制在几千行内，DP 表 ≤ 16MB、实测 2000×2000 行 **39ms**，性能无虞；
- 实现 ~40 行、无回溯歧义、正确性可用朴素用例直接断言，**维护成本低于 Myers 线性空间分治版**（本项目前端无框架无构建链，简单可读优先）。

**兜底**（界面永不卡死）：

- 剩余段超限（约 2000×2000 或合计 3 万行）→ 整段降级为"全删 + 全增"，顶部提示"未做行级对齐"；
- 后端本就按 256KB 截断正文，另有 DOM 渲染上限 15000 行（超出提示只渲染前 15000 行）；
- **二进制**（后端按 NUL/非 UTF-8 判定）→ 不出表格，提示"文件工具只支持文本类文件，二进制请用系统默认程序打开"；
- 快照正文已被清理（hasBody=false）→ 退化为只展示当前内容（不着色）并说明；
- 当前文件已被删除 → 整篇红（删除）。

### 右栏视图（`rpRegister('file')`，app-chat.js 1687 行起）

与「子对话 / 计划 / 浏览器」同一套页签机制：`rpOpen('file')` 打开、`order 2.5` 排在计划与浏览器之间；会话态经 `saveSession`/`restoreSession` 记住"这个会话正在看哪个文件的哪次改动"，切走再切回自动恢复；手动点开页签而无查看记录时给空态引导。

### 展示细节（style.css 653 行起，`fvw-*` / `fdiff-*` 前缀）

- **行号两列（旧/新）**：未变行两列都有号，删除行只有旧号、新增行只有新号——一眼看出行挪动；横向滚动时两列 sticky 钉在左侧（偏移 `--lno-w` 由 JS 按首列实际宽度写入）。
- **长行**：默认横向滚动（保持行对齐直觉，同 GitHub/Git），顶栏「折行」按钮切换为折行显示。
- **红绿**（视觉口径对齐 ZCode 源码 `packages/ui/src/components/ui/lightweight-diff-preview.tsx` 的轻量 diff）：改动行 `color-mix(in srgb, var(--green|–danger) 13%, var(--code-bg))` 铺底，行号列 18% 同色 + 左缘 3px 竖条（inset box-shadow）；颜色从主题变量派生，**深浅色主题各自可读**。
- 等宽字体 `Consolas, "Courier New", monospace`（与文件改动面板路径、历史版本正文一致）；中文 UTF-8 全程无乱码（split 前统一 CRLF/LF 归一）。
- 新建文件 = 整篇绿；二进制 = 提示条说明，不出表格。

## 四、30 秒自测步骤

1. 构建并替换正在运行的 exe（或用 `-webdir web` 开发模式），打开任意有文件改动的会话；
2. 展开「文件改动 · 修改 N / 新增 M」折叠条；
3. **点某个文件行的路径文字** → 右侧栏展开「文件」页签，整文件红绿视图：绿 = 本次新增、红 = 本次删除，行号两列随行变化；顶栏显示"旧 N 行 → 新 M 行 · +a / -d"；
4. 点行内**「历史版本」按钮** → 仍然就地展开历史版本列表（与改动前行为一致）；点列表里的「查看内容」照旧展开正文；
5. 顶栏「折行」按钮切换长行显示方式，「⟳」重新读取；右栏「✕」或切换页签关闭；
6. 切到别的会话再切回来 → 右栏「文件」自动恢复到该会话上次查看的文件与改动。

## 五、已知限制

- 只支持**文本类文件**（代码/配置/markdown 等）；二进制（Word、PPT、图片、exe 等）给提示不渲染——这是有意取舍（按需求只看代码文件），Office 预览不在范围。
- 正文受后端快照口径 256KB 截断，超长文件 diff 基于截断内容（有提示）；DOM 超过 15000 行只渲染前面部分（有提示）。
- 差异段极端超大（约 2000×2000 行以上）时退化为整段红绿、不做行级对齐（有提示）。
- 行级 diff 无词级（字符级）高亮；无语法高亮（项目前端无构建链，暂不引 shiki 类依赖，后续可加）。
- 手机窄屏下可用（右栏浮层整屏 + 字号略收），但行号两列 + 横向滚动的布局在窄屏体验一般，未做专项优化。
