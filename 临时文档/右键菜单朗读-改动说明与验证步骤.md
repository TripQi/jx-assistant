# 右键菜单「朗读」全覆盖 — 改动说明与验证步骤

> 日期：2026-10-23 · 范围：前端（`web/`、`组件/voice/client.js`）+ 文档
> 约束：本改动**未**在运行中的客户端里生效（前端经 `go:embed` 内嵌，未 rebuild、
> 未重启）——需要用户手动重启后逐项验证，清单见文末。

## 一、做法（一句话）

朗读仍然是**语音组件**的东西（后端 `/api/voice/tts`，Edge「大声朗读」通道）。
应用本体只多做一件事：**把「这个右键目标该念什么」算出来交给组件**
（`app-core.js` 的 `ctxSpeakItems(ctx)` → `JX.ctxMenuItems`）。
「朗读」条目由 `组件/voice/client.js` 的 `ctxMenuFn` 生成，组件关掉即注销——
菜单里连条目带分隔线一起消失，不会留下点了没反应的项。

- 没有第二套发音代码：分块合成、音色语速、**单飞**（同一时刻只读一条）、
  朗读中变「停止朗读」，全部复用原链路（与消息操作行的朗读按钮同一个 `ttsPlay`）。
- 没有第二个菜单渲染器：桌面壳与左栏都走左栏的 `openCtxMenu`。

## 二、盘点：前端一共几类右键菜单（10 类，全部接入）

| # | 菜单 | 生成处 | 原有条目 | 朗读念什么（取值口径） |
|---|------|--------|----------|------------------------|
| 1 | 对话区**文字选区** | `web/app-ctxmenu.js` `selectionMenuItems` | 复制 / 引用到输入框 / 问AI | 选中的那段字 |
| 2 | **消息气泡** | 同上 `bubbleMenuItems` | 复制全文 | 有选区→选区；否则气泡可见文字（**跳过 `<pre>/<code>` 与按钮**，念代码只是噪音）。注意「复制全文」仍取 `innerText`（代码要一起复制），两者口径不同 |
| 3 | **网页链接** | 同上 `linkMenuItems` | 打开 / 在系统浏览器中打开 / 复制链接 | 链接文字；图标链接没有文字→念 URL |
| 4 | **文件路径链接** | 同上 `fileMenuItems` | 预览（右栏）/ 在系统中打开 / 在文件夹中定位 / 复制路径 | `文件 名，路径 全路径`（`speechPathText`） |
| 5 | **交付卡文件行** | 同上 `deliveryMenuItems` | 打开 / 在文件夹中查看 / 预览（右栏）/ 复制路径 | 行内可见文字（文件名 + 大小）+ 完整路径 |
| 6 | **工具调用截图** | 同上 `imageMenuItems` | 在右栏查看 / 复制图片 | 图片 alt；没有 alt→文件名 |
| 7 | **输入框（编辑菜单）** | 同上 `editMenuItems` | 撤销/重做/剪切/复制/粘贴/全选 | 有选中→选中；否则框内现有内容（草稿/引用） |
| 8 | 左栏**会话项** | `web/app-left.js` `openSessionMenu` | 重命名 / 恢复自动命名 / 标为未读 / 分支对话 / 移入回收站（回收站视图：恢复 / 重命名 / 彻底删除） | `标题，工作区 名` |
| 9 | 左栏**工作区头** | `web/app-left.js`（正常视图与回收站两处 `wa-more`） | 重命名 / 复制路径 / 资源管理器打开 / 移入回收站（回收站：复制路径 / 彻底删除目录） | `工作区 名，路径 目录` |
| 10 | 右栏**子对话清单项** | `web/app-right.js` `openSubItemMenu` | 重命名 / 未读 / 分支对话 / 移入回收站 | `AI 子对话，标题` 或 `人工子对话，标题` |

**本来就没有右键菜单、因此这次不新增的**（如实列出，避免误以为漏了）：
设置页各项、待办卡、进度面板条目、回收站分组头（只有「…」按钮，右栏同款在正常视图才有右键）、
右栏抽屉其余元素。给它们凭空造一个只放「朗读」的菜单属于超范围，没做。

## 三、取值口径（统一规则）

1. **选区优先**：选区必须落在被右键的那个目标内部（`speechSelectionIn`）——
   不会因为刚才在对话里划过一句，右键文件项就把那句念出来。
2. **否则取该目标的可见文字**（`speechTextOf`）：按文档顺序收集文本节点，
   **跳过** `PRE/CODE/KBD/SAMP/SCRIPT/STYLE/SVG/BUTTON/INPUT/TEXTAREA/SELECT/IMG`
   与 `.hidden` 子树；文件类用 `speechPathText`（文件名 + 全路径）。
3. 交出去的原始文字再到组件里过一遍 **`cleanForSpeech`**（剥 markdown、压空行）；
   **剥完为空就不出条目**（例如只选中一段代码）——避免死点。
4. 文件/会话/工作区这类「没有正文」的目标按可见信息组一句（见上表），
   口径都写在对应函数的注释里。

## 四、第二块：右栏浏览器面板内的右键（只调研，未实施）

结论：**先不做**。技术上要 `ICoreWebView2_11::add_ContextMenuRequested` +
`ICoreWebView2Environment9::CreateContextMenuItem`，绑定库一个都没导出，
必须手写 COM vtable 与回调对象；槽位错一个就是访问违例、**整进程消失**
（与今晚那次事故同型），不是「出错弹个提示」的量级。

关键事实（已从官方 IDL `WebView2.idl`（NuGet 1.0.2903.40）逐项核对，不是凭记忆）：

| 需要的东西 | IID / 槽位（0 = QueryInterface） |
|---|---|
| `ICoreWebView2_11` | `{0be78e56-c193-4051-b943-23b460c08bdb}` |
| `add_ContextMenuRequested` | `ICoreWebView2_11` 的**第 100 号槽**（99=CallDevToolsProtocolMethodForSession，101=remove_…） |
| `ICoreWebView2Environment9` | `{f06f41bf-4b5a-49d8-b9f6-fa16cd29f274}` |
| `CreateContextMenuItem` | 环境接口**第 19 号槽** |
| `ICoreWebView2ContextMenuRequestedEventArgs` | `{a1d309ee-c03f-11eb-8529-0242ac130003}`：3 MenuItems / 4 ContextMenuTarget / 5 Location / 6 put_SelectedCommandId / 7 get_SelectedCommandId / 8 put_Handled / 9 get_Handled / 10 GetDeferral |
| `ICoreWebView2ContextMenuTarget` | `{b8611d99-eed6-4f3f-902c-a198502ad472}`：3 Kind /4 IsEditable /5 IsRequestedForMainFrame /6 PageUri /7 FrameUri /8 HasLinkUri /9 LinkUri /10 HasLinkText /11 LinkText /12 HasSourceUri /13 SourceUri /14 **HasSelection** /15 **SelectionText** |
| `ICoreWebView2ContextMenuItem` | `{7aed49e3-a93f-497a-811c-749c6b6b6c65}`：3 Name /4 Label /5 CommandId /6 ShortcutKeyDescription /7 Icon /8 Kind /9 put_IsEnabled /10 get_IsEnabled /11 put_IsChecked /12 get_IsChecked /13 Children /14 add_CustomItemSelected /15 remove_… |
| `ICoreWebView2ContextMenuItemCollection` | `{f562a2f5-c415-45cf-b909-d4b7c1e276d3}`：3 Count /4 GetValueAtIndex /5 RemoveValueAtIndex /6 InsertValueAtIndex |
| 两个回调接口 | Requested `{04d3fe1d-ab87-42fb-a898-da241d35b63c}`、CustomItemSelected `{49e1d0bc-fe9e-4481-b7c2-32324aa21998}`（都只有一个 Invoke，可直接复用项目里现成的通用 `evtHandler`） |
| 版本门槛 | 1.0.1185.39（2021 年）→ 现装运行时都满足 |

**「右键位置的选中文本」能拿到吗？——能，不需要 CDP。**
`ContextMenuRequested` 回调里 `args->get_ContextMenuTarget()`
→ `target->get_HasSelection()/get_SelectionText()` 直接给选中文字（`LPWSTR`，
要 `CoTaskMemFree`）。回调在 UI 线程；自定义项的 `CustomItemSelected`
里没有选区，要在建菜单时把这段文本记在 Go 侧。

**已有底子（这才是「可做」的依据）**：`browser_panel_windows.go` 早就为面板
手写过 vtbl 镜像（`wvRawVtbl` 正好 61 槽 = ICoreWebView2，与 IDL 一致）、
通用 COM 回调（`evtHandler`）、`panelRecover` 兜 panic、UI 线程 Dispatch 投递、
CDP 调用通道。也就是说**不是从零开始**，但**必须再对 41 个槽位与 4 个新接口
逐一核对**（我能从 IDL 读完，人也能读完——错一个就崩）。

### 分级方案

**(a) 最小可行版**：只加一项「朗读选中文字」，无选区时 `put_IsEnabled(false)` 置灰。
- 改动面：`browser_panel_windows.go` 约 250–350 行（QI 到 `_11`、槽 100 注册 handler、
  读 target/selection、建 item、挂 CustomItemSelected、保活 handler 对象、
  把文本交给现有 TTS）+ 一个配置开关。
- 崩溃风险：**中高**。踩点：槽位算错 → AV 直接杀进程；handler 被 GC 回收而原生
  仍持有 → use-after-free（库自己注释里也承认这个 unsafe 约束）；在非 UI 线程
  调 `add_*` → `RPC_E_WRONG_THREAD`（这个只是 HRESULT，不崩）。
- 代价：一晚不一定收得住，而且**崩了就是整个客户端消失**，用户正在跑的对话全没。

**(b) 完整版**：`朗读选中文字` / `停止朗读` / `朗读页面正文`（`Runtime.evaluate`
取 `document.body.innerText` 再清洗）/ 子菜单分类。代价 = (a) 的 1.5 倍，风险同源。

**(c) 旁路（低风险，但不是原生菜单）**：往面板页面注入一段 JS（`addScriptToExecuteOnDocumentCreated`
已可用），自己画一个页面内的浮动菜单，回传选中文字给宿主 → 宿主转给主界面 →
组件发音。风险接近零（没有新 COM 接口），但**会顶掉网站自己的右键菜单**
（Google Docs / 地图这类站点会难受），观感也不统一。不建议做成默认。

**如果哪天真要上 (a)/(b)，必须这样做**（否则别动）：
1. 先写一个**独立探针 exe**（照 `gui-test/dpi-probe2.go` 的路子，不进主进程）：
   自建一个 WebView2 窗口，QI 到 `_11`、注册 handler、插一项、打印选中文字。
   探针崩了只崩探针，槽位对不对当场就见分晓。
2. 探针通过后再进面板，且**必须在 `config.json` 加显式开关**（例如
   `"browserPanelSpeakMenu": true`，**默认 false**）。回退 = 删掉/关掉该开关
   重启，或直接把注册那段代码注释掉，行为立刻回到「Edge 原生菜单」。
3. handler 对象按项目既有做法字段常驻（`retire/unretire` 那套），不靠局部变量活着。

### headed 独立窗口（`browser_open mode=headed`）：做不到

那是我们自己 `chromedp` 拉起来的**另一个 `msedge.exe` 进程**（独立 profile，
走 CDP 编程接口）。既然不是宿主，就没有 `ICoreWebView2` 这个 COM 对象，
**没有任何 API 能往别人家浏览器的原生菜单里插项**。
唯一旁路是塞一个自建扩展（`--load-extension` + `chrome.contextMenus`），
代价是改启动参数、往用户 Edge 里装扩展、跟窗口生命周期耦合——不建议做。

### 网页 / 手机模式同理

`app-ctxmenu.js` 只在 `desktop-shell` 形态注册（桌面壳把 WebView2 默认菜单关了，
才有必要自绘）。网页与手机形态里，聊天区的右键是**浏览器自己的原生菜单**，
我们碰不到；不过左栏会话项、右栏子对话项、工作区头这些 **app 自己的菜单已经带上朗读**。

## 六、验证

### 已做（本机，不重启客户端）

```sh
node --check web/app-core.js && node --check web/app-ctxmenu.js \
  && node --check web/app-left.js && node --check web/app-right.js \
  && node --check 组件/voice/client.js
node gui-test/ctxmenu-speech-test.js      # 74 pass, 0 fail
```

桩测覆盖：10 类菜单都含且仅在末尾含一条朗读（前面有分隔线）；朗读中文案全部变
「停止朗读」且点击真停；组件未启用时**一条都不出现、也不留尾部分隔线**；
代码块/外部选区不参与取文本；文件念「文件名 + 路径」。

### 待用户重启后逐项点一遍

1. **设置 → 内置组件**，确认「语音」处于启用状态。
2. 盯着一个会话，依次右键：
   - 对话区**选一段文字**再右键 → 复制/引用到输入框/问AI/**朗读**；点朗读应出声，再右键同一处应显示**停止朗读**；
   - **消息气泡**空白处右键 → 复制全文/朗读（念正文，**不该念代码块**）；
   - 正文里的**网页链接**→ …/朗读（念链接文字）；
   - 正文里的**文件路径**（反引号里的 `xx.md`）→ …/朗读（念「文件 名，路径 全路径」）；
   - **交付卡的文件行**右键 → …/朗读（念文件名、大小、路径）；
   - **工具调用截图**右键 → …/朗读；
   - **输入框**右键（有草稿）→ …/朗读（没选中就念整段草稿）；
   - 左栏**会话项**右键 → …/朗读（念「标题，工作区 名」）；
   - 左栏**工作区标题行**的「…」→ …/朗读（念名与路径）；
   - 右栏子对话下拉里的**子对话项**右键 → …/朗读。
3. **单飞**：从气泡点「朗读」，趁它还在念，立刻右键左栏另一个会话点「朗读」——
   应只剩后一条在念，且任何菜单此时都只显示「停止朗读」。
4. **组件关掉**：设置 → 内置组件 关掉「语音」→ 上面每一类菜单里**都不应再出现朗读项**
   （也不应该多出一条空分隔线）；重新打开后自动回来。
5. 右栏**浏览器面板内**右键：仍是 Edge 原生菜单（本次没做，见第四节）；
   `headed` 独立窗口同理。
