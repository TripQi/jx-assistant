# 子对话动态反馈到主对话侧栏行——改动说明与验证步骤

## 背景与目标

主对话自己的完成/运行状态在左侧栏那一行有提示（绿点=完成未查看、⟳ 运行中），
但它名下**子对话**的动态完全不可见——人工在右栏建的子对话干完了活，用户不知道
是哪个主对话建的。目标：子对话的运行/完成状态反馈到侧栏父对话那一行。

## 改动点（web/app-chat.js、app-left.js、app-right.js、style.css）

1. **完成 → 父行绿点**（app-chat.js handleGlobalEvent）：`done` 与 `sub_end`
   事件发生在子对话上、且右栏没正看着它时，`dotDone` 同时标到父会话——侧栏
   父对话那行亮起与主对话同款的「完成未查看」绿点。清除语义沿用现有口径：
   打开主对话即清；若右栏恢复显示的正是那个子对话，它的绿点也随之清（打开
   即视为已读——正是"看到成果"的路径）。`report_ready`（AI 派发链路）本来就
   标父，本次补齐的是人工/右栏子对话的 done/sub_end 链路，两条幂等互备。
2. **运行中 → 父行状态位**（app-left.js）：STATUS_CELLS 新增 `subrun`——顶层
   会话自己空闲但名下有子对话 running 时，时间位显示同款「⟳ 运行中」，悬停
   title 说明是子对话在执行。优先级：待确认 > 自己运行 > 子对话运行 > 已中断。
   实时性由既有 `session_updated` → loadSessions → renderSessionList 链路保证。
3. **下拉补完成绿点**（app-right.js + style.css）：子对话下拉状态格从三态扩为
   四态（运行中圆环 > 完成绿点 > 未读红点 > '·'），不用逐个点开找哪个完成了；
   打开该子对话即清（openSubSession 与主对话 openSession 同款 delete dotDone）。

## 行为边界（与既有语义一致）

- 「正看着」判定用现有 `subViewing`（右栏当前显示的就是这个子对话）：看着它
  完成不算未读，不标父。
- `dotDone` 是内存态（与主对话绿点同源）：页面刷新后绿点消失，会话运行态/侧栏
  状态位仍在（来自服务端数据）。
- 已归档子对话不计入 subrun 判定。

## 验证步骤（已实测通过，2026-10-19）

隔离实例 `-webdir web`，事件流探针 + 页面断言：

1. 右栏建子对话发长任务 → 回首页（没看着）→ 侧栏父对话行 `dot done` 绿点亮起，
   `dotDone` 同时含子会话与父会话 id。
2. 右栏正看着子对话完成 → 不标（既有语义回归确认）。
3. 打开主对话 → 父行绿点清；右栏恢复显示那个子对话时其绿点一并清。
4. 子对话 running 期间（已回首页）→ 侧栏父行时间位 `⟳ 运行中`（subrun）。
5. 下拉状态格 `d-status done` 绿点渲染正确；`s-time`/`⟳`/`dot` 各态与主对话
   行为一致。
