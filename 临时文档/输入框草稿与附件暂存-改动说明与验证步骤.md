# 输入框草稿串对话 + 附件暂存跨对话通用——改动说明与验证步骤

## 现象

在任意对话里打了字（还没发），切到别的对话，这些字会跟着过去；切得越多，越像
「所有对话共用一个输入框缓存」。引用胶囊也像跟着走（其实是输入框文本里的
`“引用N”` 标记被搬过去了）。

## 根因

`web/app-chat.js` 的引擎顺序错了（2026-10-18 提交 `f00195ff3a`「field-sizing +
草稿落盘防抖 300ms」引入）：

```
openSession → optimisticSwitch（先把 st.cur 改成目标对话）→ applySessionChrome
                                                              └─ flushMainDraft()  ← 在 cur 改写之后
                                                                 落盘按「当前 cur」认目标
→ 把源对话输入框里的字写进了目标对话的草稿键 jx.st.<目标id>
→ 随即又从该键读回来贴进输入框 ⇒ 切到哪个对话都带着同一份字
```

当天之前是逐键即时落盘、切换时只读目标草稿，所以不会串；坏的是那次「落盘防抖」
改动把 flush 放到了 cur 改写之后。子对话（`openSubSession`）同一条链路、同一个错。

## 改动

1. `optimisticSwitch`：`st.cur = {...brief}` **之前** flush（源对话的字落回源键）。
2. `applySessionChrome`：删掉里面那行 flush，只负责「贴目标对话的草稿 + 引用」。
3. `loadSessionInto`：`state.cur = data.meta` **之前** flush（覆盖「会话列表里查不到
   brief、不走乐观切换」的慢路径）。
4. `web/app-right.js` `openSubSession`：`subState.cur = data.meta` **之前** flush，
   删掉数据落地后那处顺序已错的 flush。
5. 附件暂存区恢复「所有对话通用」：删掉 `renderAttachments` 里「换了会话这一轮的
   附件不跟过去」的清理与整套 `attachSid` 标记。只有发送成功（`clearAttachments`）
   才清空——手机壳把文件分享到新建对话页、再挑一个对话发出去，靠的就是这份暂存。

## 行为约定（改动后）

| 东西 | 归属 |
| --- | --- |
| 输入框文字 | 按对话：首页 `jx.homeDraft.text` / 主对话 `jx.st.<id>` / 子对话 `jx.subst.<id>` |
| 引用（胶囊 + `“引用N”` 标记） | 按对话：`jx.homeDraft.quote` / `jx.q.<id>` / `jx.subq.<id>` |
| 暂存附件（输入框上方那排卡片） | **全局一份**，切对话/回首页都不清，发送成功才清 |

取舍：附件标记（`“验证报告.docx”`）属于正文文本、跟着各对话的草稿走，附件卡片全局。
所以跨对话时新对话的输入框里没有该标记（不高亮、也不影响发送——发送靠
`flushAttachments` 的注记拼「用户附件：」块，不依赖标记）；切回原对话标记与卡片都在。

## 验证（已实测）

隔离 mock 实例（`-config <临时配置> -port 8811 -webdir web -noopen -browser`，
`baseURL: mock`，数据目录落 `.jxai/tmp/`），用浏览器工具在真实页面上跑：

1. 首页输入 `HOME-草稿` → 开会话甲（输入框空）→ 甲里输 `AAA-草稿` 后**立刻**切乙
   （防抖 300ms 还没落，最坏情况）→ 乙输入框 **空** → 乙输 `BBB-草稿` → 切回甲
   ⇒ `AAA-草稿` → 切乙 ⇒ `BBB-草稿` → 回首页 ⇒ `HOME-草稿`。
   localStorage：`jx.st.<甲>=AAA-草稿`、`jx.st.<乙>=BBB-草稿`、`homeDraft.text=HOME-草稿`
   （三份互不污染）。
2. 引用：甲里引用一段话 → 切乙 ⇒ 引用胶囊 `display:none`、`state.quotes` 长度 0 →
   切回甲 ⇒ 1 条、胶囊可见。
3. 附件：甲里挂 1 个文件 → 切乙 ⇒ 卡片仍在（1 个）→ 回首页 ⇒ 仍在（1 个）。
4. 反向复现（同一套断言跑旧代码：把 `applySessionChrome` 里那行 flush 放回原位）：
   切到乙时输入框显示 `AAA-草稿`，切回甲又变成 `BBB-草稿`，两个会话的草稿键都被写成
   `BBB-草稿`——与用户报的现象一致，确认这条断言抓得住这个 bug。
5. `node --check web/*.js` + `go build` 通过。

`cdp.mjs` + 一个 mock 实例写成 mjs 固化下来）。
