> 2026-10-30。对应提交：`0087ec6239`（审批卡自愈）、`d14154a5a4`（打开优先/下载链路，前后端）、`1dde78e4d1`（jx-link 壳 20261030-1）、`405740f7d0`（手机端图标）。
> 用户主诉：① 远程时计划正文在对话区显示出来了、审批卡（批准面板）却不出现，退出远程重连才好、经常要退两次；② 手机端交付文件下载后只保存不打开，希望「下载并打开」；③ 远程下载由网页闷头整文件加载完再抛给浏览器，没有进度条，大文件像卡死。

## 一、计划审批卡不出现（根治）

### 根因
- 审批卡的数据源只有两个：全局 SSE 广播 `question_required`（**一次性、无回放**）与启动时/兜底轮询的 `loadQuestions()`。
- 远程模式 SSE 走 210 网关中继，**单请求 150s 上限必被掐断**，断开后 3s 重连——重连窗口里广播的事件永久丢失；20s 兜底轮询只在 `readyState!==1` 时才拉，SSE 三秒内已重连回去，轮询被跳过 → 审批卡永远不出现。
- 计划**正文**走的是会话自己的流（有「接回执行流」机制），所以「正文有了、批准卡没有」。
- 手机后台回来时 SSE 可能假死（未报错、`readyState` 仍 1）同理丢广播；「退出再进来」实际上是冷启动重新 `loadQuestions`，所以能好——「要退两次」是壳热路径保留了旧页面现场，根本就不需要重载，本次改造后**原地面板自己回来**。

### 改动
| 文件 | 改动 |
|---|---|
| `web/app-chat.js` `connectEvents` | SSE **重连**成功（`onopen` 且非首次）即补拉 `loadApprovals()+loadQuestions()`（此半边随 efeafbdbbf 入库） |
| `web/app.js` | 监听 `jx:tunnel`（隧道首通 / P2P 直连建立 / SSE 重连成功，remote-boot 派发）→ 补拉；`visibilitychange` 回前台 → 补拉（手机后台回来场景） |

### 验证（远程实机）
1. 手机远程连接电脑，让助手进计划模式出一份计划。
2. 若审批卡已出现——在电脑端把 SSE 掐一次（等 150s 或重启电脑端服务），手机端再让助手出计划，观察断线窗口后的几秒内审批卡是否自动出现（重连即补拉）。
3. 手机切后台 1~2 分钟（跨越一次计划提交）再回前台：审批卡应在回前台后很快出现，不再需要退出重连。

## 二、交付卡「下载」：纯下载收敛（2026-10-30 17:13 用户定稿）

> 中间版本曾做「打开优先、自动降级 + inline + 页内进度条」，按用户反馈全部收敛：
> 主按钮就是「下载」；查看类需求由已有的「右侧打开」承担（图片/网页/md 它本来就管）；
> 不做页内进度条，下载交给浏览器自己的呈现；手机壳每次都是**下载并打开**，
> 开始下载就提示（不等下载完）。

### 最终行为
| 环境 | 「下载」按钮 | 提示 |
|---|---|---|
| 手机壳 jx-link（20261030-1） | 壳下载管理（流式分块过桥，不再整文件 blob 化）→ 完成后**自动调系统应用打开**（openDownload 桥） | **开始下载即 Toast**「正在下载到「下载管理」：<名>」；完成信号 = 自动打开 |
| 手机壳（旧壳未更新） | 同上但不自动打开（网页检测不到 openDownload 桥） | 完成时旧壳自己的 Toast |
| 远程浏览器（电脑/手机 Chrome 等） | 经隧道**流式**取字节 → 浏览器原生下载气泡落盘（不弹保存框） | 浏览器自己的下载呈现 |
| 局域网直开（浏览器） | a[href] attachment 原生下载 | 浏览器进度条（Content-Length 已报准） |
| 本机（localhost） | 「打开」（系统程序），不变 | — |

### 为什么远程浏览器仍是「页面取字节再交浏览器」
原生下载要求浏览器引擎自己发 GET 够得着那个网址；远程模式页面挂在网关源上（API 在家端、只有页面里的加密隧道能访问），引擎直连打不到家端——这是远程形态的上限，收尾交给浏览器气泡是最接近原生的做法。流式取字节免整文件二次占内存。

### 改动（相对 2026-10-27 基线）
- `server.go`：交付下载接口显式 `Content-Length`（本地/局域网原生下载进度准确；远程隧道 head 帧透传）。
- `remoteaccess.go` `bridgeCore`：head 帧透传 `len`（响应总大小，隧道元数据保真；gzip 场景为解压前长度，消费端解压后字节数正好等于它）。
- `web/remote-boot.js`：head.len 还原成 Response 的 Content-Length（中继/直连两处）；`downloadURL` 重写——壳桥路径删重复实现改委托 `jxShellSaveURL`；浏览器路径流式取字节+blob 气泡。
- `web/app-chat.js`：`deliveryDownloadFile` 三通路分流（壳/远程/局域网）；`jxShellBridge` 补父窗口链查找（iframe 形态壳桥挂顶层）；`jxShellSaveURL` 改流式分块过桥 + 完成后调 `openDownload`。
- `jx-link`（20261030-1）：新桥 `JXLink.openDownload(id)`（FileProvider+ACTION_VIEW）；打开逻辑与 `DownloadsActivity` 统一（`openItem`），mime 为空/octet-stream 按扩展名查 MimeTypeMap 兜底（否则 docx/xlsx 被拒开）；**beginDownload 即 Toast 开始提示**、finishDownload 不再 Toast（完成信号交给自动打开）。

### 兼容性
- **旧壳 + 新网页**：下载正常，只是不自动打开（检测不到 openDownload 桥就只保存）。
- **新壳 + 旧网页**：壳行为兼容（旧网页不调 openDownload；开始 Toast 照出）。
- 桌面本机（localhost）交付卡行为完全不变。

### 验证
- 已做：`go build` 通过；`go test -run TestBridgeCore .` 全过（新增 `TestBridgeCoreHeadLen`）；JS `node --check` 通过；静态页加载烟测关键函数落位；APK 内验证（openDownload 桥、开始提示字符串、新图标均在包内）。
- 远程实机（需网关环境）：
  1. 手机壳装 20261030-1 → 交付卡点「下载」：立即 Toast「正在下载到「下载管理」」，完成后系统应用自动打开（docx→WPS 等系统关联应用）。
  2. 电脑 Chrome 远程：点「下载」后浏览器下载气泡落盘（无保存框）。
  3. 局域网浏览器直开：原生下载带准确进度条。
  4. 手机后台跨计划提交再回前台：审批卡自动出现（见第一节）。

### 已知边界
- md/图片等的**查看**走「右侧打开」（右栏渲染页/iframe 预览，远程与手机本来就有）；「下载」按钮对所有类型都是下载文件本体。
- 电脑浏览器远程端「下载后自动打开」受浏览器安全模型限制（网页无法启动本地程序），按用户口径妥协为浏览器气泡落盘；手机壳由 openDownload 桥实现。
- 电脑端新 exe 需走正常发版流程（engine 包）后远程端才生效；远程外壳有 shell-hash 自愈，家端更新后旧手机端下次打开自动拉新外壳。
