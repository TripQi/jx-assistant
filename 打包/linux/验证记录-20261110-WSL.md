# Linux 版 WSL 验证记录（2026-11-10）

环境：WSL2 Ubuntu 24.04 · 内核 6.18.33.2-microsoft-standard-WSL2 · x86_64 · systemd running
产物：`打包/linux/jx-assistant-linux-amd64.tar.gz`（18.6 MB，sha256 `cc422c40565d7e12e49b1a21dcd029ab1f15f1b3d0c374aba57b8d8ca46abb31`）
构建：`GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w"`（go1.26.5，一次通过）
二进制：ELF 64-bit x86-64，**静态链接**（`ldd` → not a dynamic executable），无任何运行库依赖。

## 一、启动与 headless 服务模式（隔离环境）

- 独立目录 `/root/jx-linux-test`（config/data/技能/工作区全在其中）、独立端口 9377、
  `bindHost 0.0.0.0`、`remoteAccess.enabled=false`、`registryURL=off`——不碰任何其他实例。
- `./jx-assistant -config config.json -noopen`：启动干净（无报错、无 WebView/图形依赖），
  日志正常打印监听地址与离线演示模式标识；`curl http://127.0.0.1:9377/` → **HTTP 200**，
  返回完整前端 HTML；`data/jx.db`（sqlite）正常建库。
- 进程驻留 RSS ≈ 31–52 MB。

## 二、Windows 浏览器访问网页端（WSL2 localhost 转发）

- Windows Edge 打开 `http://localhost:9377`：**完整可用**。
- 首页加载：全部静态资源与 `/api/*`（sessions/status/models/components/events SSE…）均 200。
- 首次向导可跳过（`POST /api/config` 正常落盘）。
- **执行小任务（全链路）**：发送「请用 run_command 执行 echo linux-ok 并告诉我输出」→
  数字助理派发子任务 → 子会话真实执行 3 步（`write` 创建 mock-演示.txt → `run_command`
  echo → `deliver_result`）→ 摘要回传主对话 → 最终答复呈现：
  「主对话 → 派发 → 子会话执行 → 压缩摘要回传 的完整链路均正常」。
  工具产物已核实在磁盘：`workspace/mock-演示.txt` 内容正确（0600 权限）。
- 结论：Linux 二进制上 LLM 主循环、工具执行（文件/shell/交付）、子任务编排、SSE 流式
  前端链路全部真实工作。

## 三、优雅降级（无桌面壳环境）

- `-desktop` 参数：启动明确报错退出（码 1），不崩溃不挂起：
  `[voicetype] 独立语音输入法仅支持 Windows，本平台跳过自动拉起`
  `桌面模式启动失败: 桌面壳仅支持 Windows（本平台请用浏览器模式）`。
- 默认浏览器形态 + `-noopen` = 纯 headless HTTP 服务（生产形态）。
- `SIGTERM`：10 秒内优雅退出（systemd `stop` 路径可用）。
- 附带确认：UDP 2230 被占时自动「退化为纯轮询」（同机第二实例不冲突）。

## 五、Linux 版功能限制清单（随 README-Linux.md 分发）

- ❌ 桌面窗口壳 / 系统托盘 / 关窗驻留（`-desktop` 报错；浏览器访问是唯一形态）
- ❌ 本地语音听写组件、独立语音输入法（voicetype，Windows 专属）；云端听写不受影响
- ❌ 密钥系统保护（无 DPAPI）：明文落盘，config.json 0600，注意安装目录权限
- ❌ 随包内置组件（危险命令护栏/待办/Git 面板/语音/cua/windows-mcp 等）：本包不含，
  组件机制本身可用（启动日志 `[组件] 发现 0 个`），后续可经服务端分块/市场分发
- ❌ 程序内静默自更新（Windows 机制）：升级用 `install.sh` 重跑
- ✅ 网页端全部核心能力、run_command/run_python/文件工具（sh + Landlock 沙箱）、
  远程工作区（内嵌 amd64/arm64 helper）、技能市场、远程接入、更新检查

## 六、已知事项

- WSL 专有：`wsl.exe` 会话全部退出后 VM 空闲约 1 分钟自动关机，nohup 进程随之终止——
  这是 WSL 平台行为，真实 Linux 服务器无此问题（systemd 常驻）。WSL 里长跑需保持
  一个前台会话或开启 systemd 服务（本验证即用 systemd 实测通过）。
- 更新源（jxai-server `/updates/latest`）当前没有通用附件通道，Linux tar.gz 尚无法随
  `publish-update` 上传；install.sh 已按资产名匹配，服务端补通道后自动可用（见
  AGENT.md「Linux 版发行与发版」节）。
