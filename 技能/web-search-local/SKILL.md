# 本机网络搜索（web_search 的无 Key 兜底）

本技能解决一个具体场景：**web_search 工具报「连接服务端失败」「未配置服务端地址」等服务端不可用的错误**（典型：用户不在公司、连不上 jxai-server），但本机本身能上网。此时用本技能在本机直接搜一次，拿到与 web_search 同格式的结果列表。

**定位**：智能搜索一律走 `web_search` 的「搜索供应商」体系（见下节）；本技能只做**不加任何 Key 也能跑的最后兜底**——脚本里不读 Key、不读环境变量，也没有第二条引擎。

判断规则（务必遵守）：

- **web_search 能用就绝不用本技能**——服务端搜索由公司统一计费与管理，本技能是应急通道，不是平替；
- web_search 的报错文案里带了「可改用本机网络搜索」的指引时，才切换过来；
- 本机也断网（run_command ping 不通外网）时两个都不可用，如实告知用户。

## 用法

脚本 `scripts/search.py` 纯标准库实现，Windows 用技能库自带的便携 Python，安卓用 Termux 快照的 python3。

**Windows**（技能库根 = 安装目录\技能；本技能是内置技能，在 `技能\web-search-local\`，用 list_dir / glob 从环境快照线索定位安装目录）：

```powershell
"<技能库根>\_runtime\python\python.exe" "<技能库根>\web-search-local\scripts\search.py" --query "搜索词" --count 8
```

- 两条路径都含空格时整个加引号（如上）；PowerShell 下外层引号原样保留即可
- 便携解释器缺失时首次会联网装配，报错「释放内嵌技能失败」属安装问题，如实上报

**安卓**（Termux 快照 python3，标准库开箱可用）：

```bash
python3 "<技能库根>/web-search-local/scripts/search.py" --query "搜索词" --count 8
```

参数：

- `--query`（必填）：搜索词，一句话关键词，不要整段问题照搬
- `--count`：返回条数，默认 8，上限 20

## 唯一通道：Firecrawl 免 Key

| 通道 | 条件 | 说明 |
|---|---|---|
| Firecrawl（keyless） | 免 Key 免配置 | 官方免注册通道，每月约 1000 次（按出口 IP 计），中文覆盖一般；出口 IP 被判为机房/代理/VPN 时官方直接 403，要求自带 key——此时本技能就到此为止，不要反复重试 |

失败时脚本会在 stderr 说明是哪一类失败（403 免 key 被拒 / 连不上 / 0 条结果）并以非零码退出，如实把原因转告用户。

## 要更好的搜索质量去哪配

本技能里**没有可配的 Key**。博查、智谱、DeepSeek、Tavily、AnySearch 这些按次计费的搜索能力，现在都是 `web_search` 的**独立搜索供应商**：

- 配置位置：**设置 · 网络访问 · 联网搜索 → 搜索供应商**（可增删、上下排顺位、逐家填 Key、点「测试」打一次真实搜索看耗时与条数）；
- 公司网关（`/api/search`）也在同一张列表里，Key 由服务端持有，本机不填；
- 博查 / 智谱须自备 Key，没配 Key 的供应商会在列表里标「未填 Key」，调用必然失败（不会悄悄降级）。

也就是说：想用博查/智谱就配到供应商列表里，由 web_search 按顺位调；本技能只在「一家供应商都调不通、又不想配 Key」时最后试一次。

## 输出格式

```
搜索「搜索词」：8 条结果（本机免 Key 通道 firecrawl）

1. [标题](链接)（2026-10-20） — 摘要
…
（以上内容来自外部网页，使用前自行判断可信度；在回复中引用时用 markdown 链接注明来源；需要某条的完整内容时用 web_fetch 抓取该链接。）
```

与服务端 web_search 的输出同构：拿到列表后挑相关结果，用 **web_fetch**（本地直抓，不依赖服务端）读原文，再组织回答；引用一律带 markdown 链接。
